# TASK-2 · 建立"集合 A"（本库全部文档类型清单）

**为什么做这件事**：Owner 定的 A/B 映射规格（见 `AB-SPEC.md`）里，**集合 A = "workflow 中可能产生的所有类型的文档"**，每项必须带 **产出方 + 产出环节**。
**而 A 现在不存在**——全库只有一堆散落的交接物名字，没有一张表。
**A 是后续一切的前提**：没有 A，就无从做 A↔B 映射、无从定寿命档、无从查"闭环有没有漏"。

**你上一批已经把 B 侧（三仓怎么放文档）清点完了（G6）。这一批做我们自己的 A 侧。**

---

## 要做的事

**逐个读** `roles/*.md`（10 份）、`pipeline.md`、`closure.md`，**把每一个"角色拿到的东西"和"角色交出的东西"提取出来**，形成一张表。

### 每条必须有这些字段

| 字段 | 说明 |
|---|---|
| **名称** | 该文档/交接物叫什么 |
| **产出方** | 哪个角色产出（角色文件路径 + `:line`） |
| **产出环节** | 落在 `pipeline.md` 的哪一环（环号/环名 + `:line`）；**找不到就写"无产出环节"** |
| **消费者** | 谁读它（角色 + `:line`） |
| **类别** | **承重证据**（判据/身份/授权/冻结引用的）还是**过程记录**（报告/提案/切片/结论） |
| **现有落点规定** | 有 → `file:line`；**没有 → 明写"无"** |
| **建议寿命档** | 长期权威 / 活跃批次 / 按引用 / 可清（四档口径见 `REPAIR-PLAN-3.md`；拿不准就标"待定"） |

### 必须做的对照检查（这是这张表最值钱的部分）

把 **A 的项** 与 **`pipeline.md` 的九环** 对照，输出**两张异常表**：

1. **有文档、但找不到产出环节** → 说明 **pipeline 可能缺环**（谁在什么时候产它？）
2. **有环节、但不产任何文档** → 说明 **那一环没有交付物**（它凭什么算做完？）

**这两张表要单独成节**，因为它们直接回答 Owner 关心的"闭环有没有漏"。

---

## 纪律

- **逐条给 `file:line`**。不许凭印象、不许概括。
- **不许发明**：找不到产出环节就写"无产出环节"，找不到落点规定就写"无"。**这两类"无"正是我们要找的东西。**
- **只读产物，只写 `.pi/investigation/**`**。
- **不要设计文档体系、不要提方案**——你只负责把 A 立出来。体系怎么设计是 Oracle 的事。
- 与已有的 `EVIDENCE.md` **分开写**（那是三仓的证据；这是本库的事实）。

## 产物

- `.pi/investigation/SET-A.md` —— A 清单 + 两张异常表
- intercom 回 ≤12 行：A 共多少项、承重证据 vs 过程记录各多少、两张异常表各几条、你认为最该给人裁的 2–3 条。
