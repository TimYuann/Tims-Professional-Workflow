Non-Negotiable Boundaries

7 条不可合并硬规则

流程的底线：任何档位都不放宽。违反任一条，本轮结论直接作废并记为 UNVERIFIED。

RULE 01
实现者 ≠ 判断者
产出该候选的作者，绝对不得对该候选给出审查、验证或复核结论。任何档位、任何紧急情况下均不放宽。
RULE 02
Driver 不实现
Driver 负责划范围、排序、发卡与交接，不写产线实现代码，确保统筹视角的客观与中立。
RULE 03
集成只有一个写者
目标基线在同一时刻只能由 Integrator 写入并消解冲突。实现者在冻结候选后立即释放写权。
RULE 04
Oracle 不产生 Owner 权限
Oracle 仅在已冻结契约范围内做技术判读。超出已定义契约的问题，必须退回向 Owner 申请授权。
RULE 05
判断者不得自行放宽判据
判据不足或存在设计缺陷时，退回由 Planner / Architect 修订补齐，审查方与验证方无权私下放水。
RULE 06
不可兼任的组合禁忌
Driver × Implementer 禁忌 ｜ Driver × 判断角色 禁忌 ｜ Implementer × 判断角色 禁忌 ｜ Oracle × 争议产出方 禁忌。
RULE 07
能力缺失只降级，不降纪律
当环境开不出独立审查会话时，结论最高只能标 UNVERIFIED，绝对不得冒充 PASS 交付。

🛑 严格的两轮硬停手机制 (Two-Round Hard Stop)

同一候选在对抗审查中经过 2 轮 仍存在 Blocker，立即停止同前提的修补！
不得被装配参数覆盖或私自放宽。打包现场直接升级给独立复核 (Oracle) 或设计方重新定界，防止低效无限试错。

Identity & Rigor

对象身份规范 (ws:v1) 与三态判定

没有确定的对象就没有确定的结论。严禁用“大体上没问题”糊弄工程验收。

不可篡改的对象身份二元组

所有交接必须序列化为基线与当前树的二元组，禁止单 token 模糊表达：

object := base=<token>;tree=<token>
token := commit:<sha> | tree:<sha> | ws:v1:<sha256>

ws:v1 确定性算法：按字节序清单计算 sha256。被删文件的 digest 必须写成 -<sha256>，确保“文件存在”与“文件被删”绝不碰撞。

三态验证判定 (Tri-State Verification)

验证结论只有三种明确状态，杜绝将环境不可用冒充产品通过：

PASS 真实入口驱动通过，且反例变异（falsification）成功抓出错误
FAIL 运行行为与冻结规格不符，确认为产品代码缺陷
UNVERIFIED 环境未就绪/临时装置失败/无法复跑。不许给产品记 PASS 或 FAIL
