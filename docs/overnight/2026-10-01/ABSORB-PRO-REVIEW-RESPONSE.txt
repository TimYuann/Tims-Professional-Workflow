总体裁定

RETURN：当前 A/B 材料不足以支持本轮 core 合入，也不足以把 146 个候选作为“已经完成实质源评估、只待落地授权”的候选集。可以保留其发现价值，并继续一个有界的补读与方法正文起草批次。

这不是因为“还有文件没读完”，也不是因为“没有运行全部上游机制”。真正的阻断是：**已出现上游原意反转、当前正文前提错误、coverage 对象错配，以及阅读记录与资格汇总不一致。**这些错误会影响“应该补什么、保留什么、是否需要新增机制”的判断。

本次 A/B 与 core 均按 0c6b11c18ba0eb35858747f61566585527b05308 读取；连接器返回的整仓 tree 与 core 子树分别匹配 0788467d…、91875114…。addon 单独按 0b821ae0… 读取；比较结果只有新增检查报告，不代表 A/B 已返修。没有读取远端 main。

我同意 addon 的 RETURN 方向，但不接受把它扩大成“所有源都必须重新全文读一遍”或“所有运行机制都必须实测才能评价其知识”。以下是独立核读后的具体裁定。

4. 不能通过 narrow 绕过采纳前置，也不能凭摘要作专业价值否定

ADJUDICATION §0.4 对 narrow/defer/reject 放宽同等回读要求，需要改得更精确。决定“不研究”、决定“不把某运行时带入本包”，与决定“删掉某专业内容”“只保留其中一句”“该机制没有价值”，不是同一种判断。

我的处理是：

**范围排除可以保留。**例如暂不引入完整云编排系统、长跑 hook 协议、教学工作区，不必先研究其每个实现细节。但应写成“本轮不引入该实现形态”，不能推导成其中的隔离、交接、暂停或恢复知识都不属于专业工作流。ORC-05/06/13 的包形态取舍可以成立，其“整个机制与责任边界直接冲突”的措辞则过宽。

**实质限缩必须有足够原文依据。**DES-27 在 R0 时就以正文膨胀为由排除语言特定例子；CONC-05 尚未读源就只留“打桩边界”；ORC-12 把夹具维护压成“落盘可重跑配方”一句。这些可以是待检验的编辑方向，不能当作已经完成专业取舍的 verdict。

**“每条都有明确补读对象”也需要纠正。**DES-24、DBG-06 的条目没有像相邻条目那样给出明确前置；同族记录可以复用，但需要可解析地指过去，不能依赖接手者猜。

最小关闭条件是修改这条消费纪律，并把未读条件下的实质删改降为探索性建议。无需把所有 defer/reject 变成强制全文阅读任务。

5. 方法知识正在被推成新流程、工具和权限

**DES-20 的“并授权未来把重复规则转为检查”必须删除。**方法可以帮助判断何时值得结构化，不能成为未来改对象、加检查或删除规则的授权来源。现有 Charter 对这一点已经足够清楚。

而且，实际 encode-lessons-in-structure 原文不是无条件脚本化：不能结构化、仍需要判断时，它要求强化说明并加入失败例子；反馈闭合也允许形成具体待办。DES-20 与 DLV-07 的“只写报告不落检查不保留”方向，遗漏了这个重要分支。

同理，“没有状态机所以无法复现关闭转移”“没有新 ADR 文件所以没有可复查接受载体”“有旧状态文字所以必须引入晋升清单与校验器”，均不能作为已经成立的必要性推导。可以保留相应机制为备选，但需要证明它解决的是当前真实缺口，而不是因为上游有这种产物，就给本包制造一个同形产物。

**最小关闭条件：**恢复“需要判断时保留说明和反例”的分支；删除方法产生未来权限的措辞；将新增文件、脚本、常备清单从默认落点改成有具体使用理由的选择。无需新增角色、validator 或常驻 gate。

二、A 的价值应保留，但不能把结构抽取当作完整机制理解

我的抽样没有支持“A 全面失实”，但已经足以否定“当前校准没有遗漏承重机制或条件”的泛化。

**有准确、可用的发现。**A1 对 validate-artifact-paths.js 的摘要保留了生产者／消费者路径一致性、窄范围 allowlist、缺文件跳过而非失败等关键边界；我完整读脚本后，认为这些静态描述有依据。它没有因此证明脚本已经在任何环境实际执行。

**也有结构抽取漏掉条件的具体例子。**A1 的 /ship 行保留了并行评审流程，但没有记录上游 Rules 中允许跳过扇出的条件：文件数、diff 规模及不触及特定高风险面必须共同满足。这是会改变“何时调用该机制”的适用条件，不是装饰性例子。该行标为 structure 是诚实限度，但 B 不能将这种摘要消费成已完整评估的工作流知识。

**支持材料可以改变主文的读法。**Matt 的 mocking.md、codebase-design/SKILL.md、DEEPENING.md 不是一句“只在边界 mock”的重复副本。它们分别涉及外部依赖的 mock、内部测试接缝、本地可替代依赖、远程但自有服务的 adapter，以及不为测试暴露内部接缝。DBG-16 可以吸收这些知识，但不能以“指认单源”替代对适用语境的协调。

**DES-10 的专业细节目前只是被点名保留，还没有展开到可采纳程度。**TSV 将意图／尝试、原子认领、同键异载荷、在途重复、未知结果、保留因果列在备注中，值得保留；但“出现了这些词”不是其操作、反例与源依据已经完整。pstack 原则提供的是重跑与崩溃收敛问题；X Money 尾段进一步区分 pending、refused、未确认结果、明确未发生效果的暂时失败，以及幂等键和批准的复用条件。只读前段后概括成统一重试或统一批准规则，会损失专业内容。

因此，A 应作为可追查的发现台账保留；其 full/structure/metadata 是作者阅读动作的自述，不能直接变成跨仓质量排名，也不能豁免 full 行的事实核对。我没有历史阅读轨迹，不能据现存文件认定作者当时确实读过或没有读过某段。

四、统计、锚点与非阻断建议

**统计应描述记录，不应冒充专业完成度。**50/55/70/8 与 37/39/64/39/4 是当前表的标签分布；即使机械计数正确，也不证明分类依据正确，更不能从 175/183 推出 1,240 条路径完成专业评估。not-assessed 面应继续单列，不把它强塞进 pending 的八行，也不拼成一个新的覆盖百分比。

还有两处明确的汇总错误需要顺手修正：来源组合七个桶相加是 183，不是旁边所说的“大于 183”；“79 组×6 文件＝482”也不成立，乘积是 474，额外路径应另列。前者是组合桶与逐仓出现次数混淆，后者是模板基数与例外混淆。它们不必单独阻断一个已经完成源核验的有界方法补丁，但不能继续作为可信统计留下。

非阻断建议集中在三件事：

**让 requery 真能接手。**诸如 ADJ PSTACK-IDEMPOTENCY 行 与正文实际使用的 DES-10 标识并不一致。直接引用现有机制 ID 和小节即可，不需要新 registry。

**保留例子，但可以调整载体。**正文不必承担所有语言示例；可以保留一个能区分正误的例子，并引用承重支持材料。不能在未读时仅凭篇幅决定删掉例子、反例或异常条件。

**把状态文字的可读性问题与权威缺失分开。**当前顶层 README 已解释历史 M1–M5 标签与现行接受状态，也明确不授予下游权限；局部旧标题确实容易误读，适合统一说明，但不足以独立论证必须新增晋升机制或校验器。
