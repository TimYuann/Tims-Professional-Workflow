# TIM · Professional Workflow

**一个与业务解耦、与运行底座解耦的工程能力库：把"怎么判断"装进角色，把流程薄到一份。**

## 这是什么

9 个工程角色文件 + 1 份流程文件。每个角色文件**单独注入一个会话就能开工**：它自己写清收什么、交什么、怎么判断、什么时候不算做完。

- **不是**工作流引擎，**不是**技能市场，**不是**某个运行底座的一部分。
- **是**一套可独立版本化（见 `VERSION`）的职责与判断方法，由下游项目按需取用。

## 给谁用

给"一次任务由多个会话分工完成"的场景：一个会话做统筹（Driver），其余会话按角色承担调查、设计、切片、实现、审查、验证、集成；争议时按需起独立复核。

## 底座必须提供的 4 个原语

本库不假设任何具体实现，但**需要底座提供这四种能力**；缺哪一种，就按 `pipeline.md §2` 的降级说明装配。

| 原语 | 需要达到的效果 |
|---|---|
| **角色注入** | 能把一份角色文件的内容完整放进一个新会话的上下文，且该会话的行为受它约束 |
| **会话隔离** | 两个会话之间的上下文互不可见；判断类角色拿不到作者的推理过程 |
| **会话间消息** | 能把结构化交接物发给指定会话，并知道对方是否收到（接收确认） |
| **工作区隔离** | 能让两个会话的写入互不干扰，并在合并时由单一方写入 |

## 怎么把角色注入一个会话

只需要达到三个效果，**不要求任何特定命令**：

1. **角色正文进去**：把 `roles/<role>.md` 的全文作为该会话的行为约束（不是只给路径）。
2. **本轮切片跟上**：同一会话再收到 Driver 附加的两层——本轮工作流切片（任务图、依赖、写窗、验收口径）与工具安排。
3. **判断侧换会话**：审查 / 验证 / 复核必须由**没有产出这个候选**的会话承担；跨会话只读产物与冻结契约，不读作者叙述。

角色文件只提供前两层；第 3、4 层由 Driver 附加，**附加内容不得改变角色自己的纪律与方法边界**。

## 三个档位怎么选

按"项目成熟度 × 本次变更风险"两条轴选，不按文件数选：

| 档位 | 常驻会话 | 适用 |
|---|---|---|
| `solo(1)` | 1 | 成熟项目里的局部改动。作者侧一个会话顺序兼任；**判断侧仍须另起会话** |
| `trio(3)` | 3 | 常规任务。A=调查+设计+切片，B=实现，C=审查+验证+集成 |
| `full(9)` | 9 | 跨边界、改权限/数据语义、存在多个自洽方案的任务 |

高风险触发条件命中任一，就必须上独立复核——**降档不降边界**。详见 `pipeline.md §2`。

## 目录

```
roles/        10 个角色文件（注入单元；工具无关，稳定；含台账管理员）
pipeline.md   唯一流程：交付链 / 装配档位 / 硬边界 / 四类依赖 / 写窗 / 停止条件 / 证据复用 / 汇合 / 授权
closure.md    闭环矩阵：每环的输入字段是否就是上一环的输出字段；每环被跳过时谁承接
SOURCES.md    上游吸收台账：每个机制来自哪个 commit 的哪一行，保留了什么、改写了什么、删了什么
identity.md   对象身份的维护者规范（唯一真源；每个用到身份的角色内联了自己的计算规则）
scripts/      check-library.py（只读自检）、identity-selftest.sh（身份正负夹具）、
              ws-identity.sh（无版本历史时的身份计算）、log-decision.sh（append-only 决策台账）、
              sync-upstreams.sh（上游同步）
VERSION       版本单一来源
docs/         设计背景、历史评审与归档（docs/archive/ 是被替换掉的旧载体，保留供追溯）
```

## 自检

```
python3 scripts/check-library.py     # 只读，可重复运行；0 = 全部通过
```

它检查：角色结构、注入契约、收据与产出的字段闭环、闭环矩阵相邻字段、死链、版本单一来源、以及"具体底座名称不得出现在库内容里"。

**它判不了**：§4 方法的实质深度、语义正确性、字段值是否真实、某次跳过是否真的合规、以及同义重复——这些交给独立审查与人审。它只兜结构与确定性回归，**不是角色工作流的 PASS，也不检验某次交接物的真实值**。

**新增库级检查的保留判据**：要能声明它保护的真实断言、一个会红的反例、常见合法变体的误报检查，以及维护成本与负责人；没有区分力或误报难控就删除。**不要求它历史上一定拦过一次事故。**
