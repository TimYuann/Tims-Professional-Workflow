# 从意图到交付：责任主轴候选

状态：**候选，尚未独立接受／整体冻结**。作者：tpw-0930-spine-executor，2026-09-30。
本稿供 Oracle 与 Owner 带回的 GPT 同轮 challenge；作者自查不构成独立验收。
依据：`docs/WORKFLOW-INTENT.md`（2026-09-30 工作副本）与本轮执行 brief。
这是设计提案，不改现行 registry，不授予实际项目权限，不定最终 Role、Skill 或 runtime。

## 1. 问题与收敛选择

要解决的问题：从人的诉求到可验证交付，谁有权改变哪种结论，别人凭什么继续，发现偏差该回到谁？
Owner 已对齐：A–F 六类判断、Voice／Driver 分工、D/E 分界、委托内自治与禁止静默转移权责。
Owner 要求先 Divergent 再 Convergent，最终极简；以下比较是本次设计工作，不是下游必经流程。

| 比较的划分 | 优点 | 反例与取舍 |
| --- | --- | --- |
| 按阶段串成需求→规格→设计→实现→验收 | 容易说明顺序 | 新领域事实会同时影响行为与系统；强制逐站返回既慢又找不准主人，不选 |
| 按宽职责合并 A/B、C/D、E/F | 交接较少 | 对齐目标不等于接受具体行为；存储方案不能决定业务状态；实现自测不能充当独立挑战，不作为统一骨架 |
| 保留六类判断，按依赖调用、按任务组合实例 | 能区分谁改结论，又可复用已有结论 | 需解释组合与独立性；本稿选择它，但不为每类判断设一个常驻 Agent |

收敛后的主张：**保留六种结论的主人，只在缺少可依赖结论或发现其失效时召回判断。**
C 横向约束 B/D；F 可以提前检查任何可验证约定。A–F 的字母是索引，不是执行序号。
一次任务可以只调用 E/F，也可以多次返回 B/C；不要求做出六份文件。
同一实例可承担多类判断，但应说明本次身份与委托；组合不能消除需要另一实际角色承担的工作或挑战。

## 2. 共用的短接口

以下六类责任只共享一项交接纪律：下游能找到**结论、适用条件、依据、决定责任与接受状态**。
可直接引用已有产物中的有界部分；有变化时附本次差分，不逐层复制定义。
尚未接受的建议可用于比较或可逆探索，不能伪装成下游必须兑现的承诺。
进入依赖它的实施前，应有适用的接受依据；作者、专业判断者与接受者可能不同。
接受权来自实际委托和政策，不来自产物标题、角色名称或“我写了这一段”。

发现偏差时，指出受影响结论、事实／假设和影响，由 Driver 找到其决定责任。
若授权已覆盖，责任方可以修订自己的结论并更新依赖；若触及保留决定，经 Voice 返回相应人类 authority。
候选：只暂停依赖争议结论的工作，保全可用结果，不自动重开整条链。
这是一种返回方式，不增加审批表、固定 gate 或新文件。

## 3. 六类责任接口

### A · Intent / Outcome：为什么做，解决谁的什么问题

- **判断与工作：**理解使用情境、目标、价值、范围和优先级；核对报告、观察与推断，识别决定方向的未知项。
- **可决定／不可改：**形成问题定义、提出目标取舍和调查建议；只在明确委托内调整优先级，不替 Owner 创造目标、接受价值取舍或扩大范围。
- **依赖：**人类诉求、使用事实、既有目标与 envelope；“查找成本高”的报告不直接证明“经常找不到”。
- **交出：**可理解的问题定义、目标与非目标、事实／假设区分及关键未知项，供 B 定行为、C/D 判断约束、F 检查结果是否回应目标。
- **召回／向上返回：**新事实改变问题解释、价值或优先级时召回 A；需要改变人类目标或保留取舍时，由 Voice 读回选择与影响，找拥有决定权的人。

### B · Behavioral Contract：交付后，外部应该看到什么

- **判断与工作：**把目标表达成场景、交互、输出、异常与可观察接受条件；用例子检查漏项与冲突。
- **可决定／不可改：**在委托内补足行为表达、提出产品选择；不能改 A 的目标、C 的业务含义，不能用方便实现的行为替代接受承诺。
- **依赖：**A 的问题定义、C 中相关语义、现有行为与政策；冲突要显露，不在规格正文中悄悄解决。
- **交出：**足以区分正确／错误行为的约定及适用条件，供 D 设计与 F 判断；默认经 Voice 向 Owner 冻结，已有明确委托的接受权照其范围行使。
- **召回／向上返回：**出现未覆盖场景、行为矛盾或必须改变承诺时召回 B；纯澄清若改变可观察结果也算变更，越过接受范围须返回原接受 authority。

### C · Domain Semantics：这些概念和规则究竟是什么意思

- **判断与工作：**界定概念、关系、状态、不变量、业务规则和上下文边界；解释同名概念何时不同、同一规则由谁拥有。
- **可决定／不可改：**在有效业务委托内裁定语义，编码已接受规则；未获委托时提出候选，不把技术偏好写成业务规则，不替 B 选择用户体验。
- **依赖：**业务事实、既有规则与其业务 authority、A 的范围，以及 B/D 暴露的具体语义疑问。
- **交出：**相关概念、规则与边界及区分性例子，供 B/D 使用、F 检查；不要求为所有任务重写完整词典或模型。
- **召回／向上返回：**revision、snapshot、状态或关系的含义冲突时召回 C；已有业务规则无法裁定或需改变保留规则时，经 Voice 返回相应业务 authority。

### D · Technical / System Design：各部分如何共同兑现承诺

- **判断与工作：**确定系统边界、共享接口、数据责任、依赖、技术取舍和可实施安排；查明变化的因果范围与回归影响。
- **可决定／不可改：**在 envelope 内选择和修订技术方案；汇合 B/C 承诺但不取得其决定权，不自行放宽安全政策、预算或人类保留边界。
- **依赖：**接受的 B/C、真实系统事实、适用质量与安全约束、资源／风险委托；私有代码也可能影响共享预算或安全边界。
- **交出：**一份足够继续的 Plan：Commitments（别人依赖什么）、Delegated Decisions（E 可自主选择什么）、Recall Conditions（何时返回），附相关上游版本与决定责任。
- **召回／向上返回：**共享责任、接口、约束或验证依据必须变化时召回 D；领域／行为变化转 C/B，安全或成本争议找对应专业责任，越界接受另找相应 authority。

判别 D/E 的问题：改变此项，是否让别人必须改变依赖的语义、接口、约束或验证依据？
若是，需作为跨边界决定处理；若否且在约束内、局部可恢复，由 E 判断。
Plan 不必枚举每个 helper：未参与讨论的合格实现者能开始且不猜共享承诺，即为所需粒度。
固定某种局部实现必须有约束依据，Planner 偏好本身不够。

### E · Implementation：在承诺内把结果做出来

- **判断与工作：**实现行为与系统方案，选择局部算法、函数、类型、重构与测试接缝；通过实现和自测发现事实。
- **可决定／不可改：**自主调整 implementation interior；可挑战上游，不得静默改写 B/C/D 承诺、扩大执行授权或以自测代替独立评价。
- **依赖：**已接受约定、Plan 与本次 Charter、真实代码与环境；初始预计文件范围通常是调查假设，明确对象禁令则是边界。
- **交出：**实现结果、相关变更与自测证据、偏离／剩余问题及受影响依赖，供 F 观察和评判；不把“写完了”作为正确依据。
- **召回／向上返回：**局部缺陷继续由 E 修正；无法保持承诺或需越过委托时说明发现，经 Driver 返回真正拥有受影响判断的责任，不能把所有问题直接退给 Owner。

### F · Verification：哪些约定成立，证据支持到哪里

- **判断与工作：**设计可观察验证、获取实际证据、评价证据与反例；可在实现前指出设计的不可观察性、矛盾或不可行假设。
- **可决定／不可改：**对明确对象与范围给出证据判断；不能改预期后宣布成功，不接受超委托剩余风险，也不授予发布许可。
- **依赖：**B 的行为、C 的不变量、D 的系统约束、已接受质量政策，以及 A 中相关目标；测试通过不直接证明目标价值已经实现。
- **交出：**对象／版本、依据、观察、覆盖限制与 PASS / FAIL / UNVERIFIED；单列实际独立性，交 E 修复、原责任方处理依据缺陷、Driver 安排后续。
- **召回／向上返回：**实现违反约定返回 E；依据冲突或缺失返回 B/C/D，目标解释失准返回 A；环境阻断记 UNVERIFIED，不把它判为产品缺陷。

候选内部组合：验证设计、观察、证据评价属于 F 的工作面；独立挑战是对评价关系的要求，不另添一个顺序节点。
E 可提供自测，F 可复用可核对的证据，但作者自查不成为独立结论。
D→E 链至少有两个实际角色承担工作或挑战；一次合适的独立挑战是否足以兼顾设计与结果，留待明确组合条件。
本候选不改变现行 A7/A8 的独立性纪律，也不以缺独立渠道为理由修改三态标准。

## 4. Voice 与 Driver：连接责任，不吞掉责任

**Voice** 连接人类与专业判断，通常与 A 紧密配合，但不等同于 A。
它对齐 envelope，读回目标和行为，解释深层取舍的行为、成本、风险与承诺影响，记录接受决定。
它可组织 B 的默认人类冻结面；单凭接口身份不能冻结 C/D，不能替 Owner 接受风险或扩大授权。
Owner 不应被要求编写 schema 设计；需要的是对可理解的范围、承诺或代价选择作决定。

**Driver** 连接内部责任：识别缺失／失效结论，找有委托的责任方，检查交接足够性，管理版本依赖与召回。
已有接受依据足够时直接安排；范围内技术调整可更新 Plan 绑定与 Charter，不反复申请文件清单许可。
它不替 D 断言架构合理，不替安全责任断言风险不变，不替 B/C 裁定内容。
不清楚归属时先定位争议；有专业冲突时交指定责任整合，不能用“流程允许”制造专业结论。
Driver 留在逻辑编排层，不定义进程、并发、队列、锁、重试等 runtime 机制。

两者的最短连接：Driver 提供待裁决问题与专业方案依据，Voice 翻译并取得人类保留决定，Driver 据接受结果恢复相关依赖。
专业裁定与执行许可分别有来源；可写的工具权限不能替代授权，授权也不能绕过工具限制。
常规交接用产物指针和短消息，不让 Owner 每次扮演转述专业上下文的人。

## 5. 四类边界检验

共同前提来自上层意图：已有可引用目标与 envelope，责任委托明确。
以下是条件推演，不是项目事实、运行验证或实际动作授权；缺少委托时不能靠示例补上。

| 情形 | 接口如何工作 | 最容易错放的决定 |
| --- | --- | --- |
| freshness 跨模块修复，内部联动在委托内 | E 暴露真实依赖；D 明确 page freshness、turn snapshot 绑定及消费者责任，引用 B/C 已接受版本／失配语义；Driver 调整安排，F 检查承诺 | 模块增加不自动找 Owner；revision 含义变化找 C，页面失配行为变化找 B，D 不以“最新”自行裁定 |
| 新增存储字段或 schema 调整 | D 评估兼容、部署与恢复；业务字段含义找 C；已有委托覆盖时做实现和验证，真正执行迁移另核动作授权 | 数据库若被明确保留，经 Voice 返回范围 authority；允许写迁移代码不等于允许执行迁移 |
| 缓存键疑似跨租户混用 | 有效委托下的安全责任查明泄露面和隔离要求，D/E 落实，F 获取隔离证据；政策内已处理风险可继续 | Driver 不自报“风险不变”；mitigation 选择不包含超阈值剩余风险接受，政策变更找其接受 authority |
| 方案要求重写 persistence layer，成本明显膨胀 | D 与估算责任比较有依据的方案，排除机会性改造；预算内可选方案由委托责任选择，Driver 重排 | 无已知合规替代且合理方案超预算时，经 Voice 找资源 authority；Driver 不能降低目标抵消成本 |

检验推导：六类接口能容纳这四例，不必新增常驻安全、成本或审批节点。
但安全／估算的专业能力与接受权仍须实际指定；“放在 D 或 F 的实例中”不是资格或授权证明。
候选：按所涉问题加载专门 profile／方法，让该实例明确承担哪项判断，不扩充固定主轴。
上述仅支持接口表达的可用性，尚无真实任务的误路由率、完整性或成本证据。

## 6. 压缩方式与最少未定点

小任务直接引用足够、仍适用的已有结论，加本次差分与委托即可继续。
例如私有转义函数已有输入、输出、错误行为和质量依据：E 自选扫描算法，F 据原约定检验；不重做 A–D。
若输入含义不清、必须改调用者或突破预算，再召回相应责任；任务小不自动免除适用独立性要求。

可以压缩：共享引用代替重复正文，Plan 三部分写在同一处，证据评价复用可核对的观察。
可以组合：A/Voice、B/C 或 D 中的专业判断按委托由同一实例承担，仍标明不同结论的主人与接受权。
按需加载：完整领域模型、专门安全／持久化／性能方法、广泛方案探索；缺口出现时加载，不每次携带全部历史。
不能因压缩消失：接受状态、关键适用条件、上层约束、召回去向，以及真实独立性。
本稿的方案比较和四类夹具用于本轮 challenge，不提议复制成每个任务的强制流程。

仅保留两个影响下一轮设计的未定点：

1. **F 的组合与独立性：**第二实际角色何时、以何种对象挑战 D→E，哪些情形一次挑战足够、哪些必须分离？需兼顾不同注意力上下文和适度成本，不能只靠把同一实例改名。
2. **实例组合的资格：**Driver 依据什么已接受配置判断组合足够，安全／估算等判断缺能力或权责冲突时谁接手？候选是既有预设加异常召回，不让 Driver 每次发明职业，也不新增常驻资格审批。

这两个问题留给 Oracle 与 GPT 合并 challenge 后明确下一轮范围；本轮不冻结答案。
无需重新讨论已接受的 D/E 分界或补授权清单，也不恢复来源吸收、业务试点或方法实施。
