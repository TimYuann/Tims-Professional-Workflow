## O2-a · 正常挑战不应自动让评价者变成作者

定位：L102、L154 的“参与形成了某项判断”。
该词过宽；首轮合并委托也用了相同措辞，这一歧义有 Oracle 委托的来源，不归为执行者新增失误。
反例：评价者指出缓存缺少租户隔离的反例，D 据此自行修订，评价者核验修订。若反馈影响过方案就算“参与形成”，它失去独立性，每次修复都需要再换评价者，造成无益循环。

建议最小澄清：提出质疑、反例或要求补证，不自动构成候选作者；实质代做被评价方案或实现时，才需按具体贡献重判对该部分的独立性。
例如 F 仅指出 snapshot 责任混淆，D 自行设计修复，F 可以复评；F 自己设计核心绑定方案后，不能把对该方案的自查称为独立挑战。
以评价对象和实际贡献判断，不靠帽子名称，也不靠“是否提出过意见”。不新增作者登记平台或第三层评审。
这是保持已有独立性目标的措辞澄清，不建议重开整套骨架或建立新硬规则。
