## 1. 逐条修（7 条阻断）

### B-1 · solo 档自相矛盾（硬边界冲突）
`pipeline.md:40` 写"单会话顺序兼任 Driver / … / Implementer"，同文件 `:49` 又写"Driver 不实现"，`roles/driver.md:12` 也写"不做实现、审查、验证"。
**修法**：solo 档**不得**让同一个会话同时承担 Driver 与 Implementer。三选一并写明判定条件：
- (a) 编排职责由 Owner 或另一个（可为轻量）会话承担，执行会话只做作者侧；
- (b) 若物理上只开得起一个会话，**如实标"当前档位不满足 Driver 独立边界，不可用"**，而不是把它写成可用档位；
- (c) 明确列出"不可兼任"的组合（至少：Driver×Implementer、Driver×任一判断角色、Implementer×任一判断角色）。
不许用措辞把它糊过去；要么给出可用装配，要么如实标不可用。

### B-2 · 跳过路径的替代收据不完整（五条）
现状：`closure.md:24-30` 只移交"职责"，但下一环按自己 §2 会**拒收**。已核实的具体缺口：

### B-3 · 机械等价判据会假放行

**修法**：等价判据必须能比较**被承诺的不变行为/语义**（例如：搬迁场景比较文件字节或内容 hash；重命名场景比较符号**及其绑定**在改动前后的对照，并证明未被改名符号的实现字节未变）。**无法证明时不得跳过独立审查。** 把反例写进角色文件的"反例"节做常驻警示。

### B-4 · Planner 擅自新增数字门禁（授权越界）

## 4. 身份规范（我的裁定，照此实现）

```
表达形式（有序优先级）
1. 有 git：commit:<sha> / tree:<sha>；base 指向基线提交
2. 无 git：ws:v1:<sha256>，清单规范化规则：
   · 每行 = 相对路径 + NUL + 该文件字节的 sha256
   · 路径以仓根为基准、一律 / 分隔、无前导 ./
   · 按路径字节序升序
   · 纳入 = 写入范围内全部文件 + 被删文件（以 - 标记，同样入单）
   · 排除 = .git/**、缓存、构建产物、__pycache__、.pytest_cache
   · 文本 UTF-8/LF；digest 小写十六进制

基线固定：无 git 时 base 清单必须在改动前生成；事后重建须标"重建"并附
        "重建 digest == 事前 digest" 的核对结果；不一致以事前为准并标异常

相等判定：① 前缀类型相同 ② digest 逐字相同 ③ 规则版本相同（v1）

跨会话移交：object 必须连同【清单文件本身或其保存路径】一起交；只交 digest 不算
```

用到身份字段的角色（driver / implementer / integrator / oracle / reviewer / verifier）都要有内联规则；**"等价树"这个未定义的自由条款从全库删除**。
