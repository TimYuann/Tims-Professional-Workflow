## 1. 根因

`eaa8eb2:scripts/ledger.sh:57-62`（v2.0.6）用词面匹配挡临时目录：

```bash
case "$ledger" in
  */tmp/*|/tmp/*|... ) 拒绝 ;;
esac
```

这一句同时错了三件事：

1. **判据取错对象**：匹配的是**输入字符串**，不是这次打开实际会落到的位置。于是
   「`cd` 到别处 + 相对路径 `tmpalias/evil/x.tsv`，而 `tmpalias` 是指向 `/tmp` 的软链」
   字符串里没有 `tmp` 词面，却真写进了 `/tmp`（C04）。
2. **覆盖面窄**：`TMPDIR` 完全不参与（C08–C10），`/var/tmp` 只靠枚举词面。
3. **判据方向反了**：`*/tmp/*` 把「名字叫 tmp、位置稳定」的合法目录也拒了（C17）——
   这是误报，它让下游在正常目录上被拒写。

## 2. 改法

### 2.1 `real_path()` —— `scripts/ledger.sh:74-122`

算法（不依赖 GNU，macOS 自带 `realpath` 对不存在的路径直接失败，`readlink -f` 同样）：

1. 相对路径先接到 `$PWD` 上；
2. 去掉尾斜杠（macOS 的 `$TMPDIR` 默认就带 `/`）；
3. 从整条路径往上找**最近一个「存在、或本身是软链」的祖先**，把不存在的尾部记进 `suffix`；
   悬空软链必须停在这里——`exec 7>>` 会跟着它走，它指向哪里就是往哪里写；
4. 该祖先是软链 → `readlink` 取 target（相对 target 按软链所在目录拼），把 `suffix` 接回去，
   回到第 3 步；**跳数上限 64，超了 `return 1`**（成环）；
5. 该祖先存在：是目录 → `cd -- "$cur" && pwd -P` 拿物理路径；是普通文件 → 父目录 `pwd -P` + 文件名；
6. 只对**「已解析的真实前缀 + 尚不存在的后缀」**做文本折叠（`normalize_path`）。
   `软链/..` 是软链**目标**之父，不是软链所在目录之父，所以折叠只能发生在软链解析之后。

### 2.2 其余部件

- `normalize_path()` `scripts/ledger.sh:124-138` —— 纯文本折叠 `.` / `..` / 空分量；
  只在第 6 步那个受限输入上用。
- `is_under()` `scripts/ledger.sh:140-142` —— **按路径分量**比前缀，`/tmpfoo` 不在 `/tmp` 下。
- 闸 `scripts/ledger.sh:144-169` —— 解析目标（失败 → **退出码 4，fail-closed**），
  再解析三个临时根（单个根解析失败只警告并跳过那一条），命中 → **退出码 3**。
- `exec 7>>`（`O_APPEND`）在 `scripts/ledger.sh:217`，锁协议 `scripts/ledger.sh:171-215`
  **一行未动**：`diff -u <v2.0.6> <新>` 只有 2 个 hunk（文件头注释 + 闸块）。

### 2.3 为什么不是「改 case 再补几条」

闸要判的是「这次打开会落到哪个目录项」。**只有把路径解析成真实路径，才有落点这个概念。**
补 `*/tmp/*` 的变体（比如加 `*/private/tmp/*`）挡不住 C04，因为缺陷不在枚举少了几项，
在于它判的东西根本不是落点。

## 3. 临时目录的定义（写进 `docs/ledger.md` 的那份）

**三类，以及它们之下的一切**：`/tmp`、`/var/tmp`、**非空 `$TMPDIR` 指向的位置**。

- `/tmp` 在 macOS 上真实路径是 `/private/tmp`，`/var/tmp` 是 `/private/var/tmp`——按真实路径判，
  所以 `/TMP`（大小写不敏感）也命中（C19）。
- **`$TMPDIR` 这一条是运行事实，不是保底规则**：它为空或未设置时整条不参与判定，
  而 macOS 的每用户临时目录 `/var/folders/.../T`（`confstr` 的 `_CS_DARWIN_USER_TEMP_DIR`）
  **不落在另外两条之下**。所以「`TMPDIR` 被清掉的环境里，这道闸对系统临时目录等于没设」——
  这句话本轮已实测（§8.3），并且**已写进 `docs/ledger.md` 的定义处**，不是只塞在边界一节。

## 6. 「目标路径本身是指向临时目录的软链」：判拒写，理由如下

**判拒写**（C12/C13），不是放行。

- 理由是**落点**，不是路径名：`exec 7>>` 跟随软链，字节落在软链目标处。这道闸要挡的结果是
  「记录丢在临时目录」，所以判「这次打开会落到哪个目录项」。
- 两个附带证据：
  - C12 里 `/tmp` 那个文件在拒写后**内容没变**（`SENTINEL-12` 原样）——说明闸是在打开**之前**
    拦下的，不是写了一半。
  - C13 里 `/tmp` 下的目标**没有被创建**——悬空软链也拦得住。
- 放行侧同样有反例（C14 / C21 / C23）：指向稳定位置的软链、目标还不存在的软链，都正常写。
  **判据是落点，不是「是不是软链」**——否则就会重演旧版 C17 那种误报。
- 代价（必须说明）：末级软链的判定发生在打开之前，「判完 → 打开」之间的替换就是 TOCTOU
  （§8.1 已构造成功）。本闸不为此加锁。

## 8. 三条边界：每一条都给「现在还能不能构造出绕过」

**三条都能构造。** 不是设想——每条都有实跑脚本和输出。

### 8.1 TOCTOU（解析 → 打开之间的窗口）：**能**

- 脚本：`.pi/review-v4/probe3/boundary-probes.sh`（P-D），输出 `evidence-boundary-probes.txt`。
- 做法：目标是一个末级软链，racer 在两跳之间原子替换它（指向 `/tmp` ↔ 指向稳定目录）；
  窗口用一条 **55 跳的软链链当 `TMPDIR`** 人工放大（`real_path` 逐个 readlink，耗 ~700ms）。
- 结果：**40 次尝试里 9 次把字节写进了 `/tmp`**（另外 25 次闸正常拒写、5 次干净落到稳定位置、
  1 次其他）。真实窗口是毫秒级，性质相同。
- 判断：可构造，闸不设防，也没有便宜修法（要防就得在打开后 `fstat` 已打开的 fd 再比一次
  真实父目录，那会把闸从「路径规则」变成「fd 规则」）。**保留为已知边界。**

### 8.2 挂载点：**能，而且不需要 root**

- 脚本：`.pi/review-v4/probe3/mount-point-bypass.sh`，输出 `evidence-mount-point-bypass.txt`。
- 做法（macOS 没有 bind mount，等价物是「把易失卷挂到稳定路径」）：
  `hdiutil attach -nomount ram://4096` → `newfs_hfs` → `mount -t hfs` 挂到
  **仓库内的一个看起来完全稳定的路径**下。**uid=501（非 root）实测全部可行**：
  `mount` 表里是 `/dev/disk10 on .../stable/mnt (hfs, local, …, mounted by yuantian)`，
  台账父目录在同一台机器上是 `/dev/disk3s5`。
- 结果：闸放行（退出码 0），台账写在 RAM 盘上；`umount` + `hdiutil detach` 之后
  **那行记录不复存在**（脚本最后断言目标已不存在）。
- 判断：可构造，闸不设防。文档里原来写「把临时目录 bind mount 到别的路径下，抓不到」——
  现在改成实测口径：**macOS 没有 bind mount，但挂一个易失卷到稳定路径是它的等价物，
  且不需要 root。**

### 8.3 `TMPDIR` 未设置时的 macOS 每用户临时目录：**能**

- 脚本：同上（P-B）。
- 做法：`env -u TMPDIR`，目标写在 `getconf DARWIN_USER_TEMP_DIR` 给出的
  `/var/folders/.../T/` 下。
- 结果：**退出码 0，文件真的落在系统每用户临时目录里（2 行：表头 + 数据）。**
- 判断：**是**——`TMPDIR` 没设、而系统实际把临时目录放在 `/var/folders` 时，这道闸
  对它等于没设。这正是你担心的情况，**已按你的要求写成条件句**（定义处 + 边界处都写了：
  「在 `TMPDIR` 被清掉的环境里（`env -u TMPDIR`、部分 cron 与 CI 任务），这道闸对系统
  临时目录等于没设」）。
- 它能不能修？把 `/var/folders/<...>/T` 硬编码进去是本机特供（每用户路径含哈希），
  不合本库的工具解耦取向。**结论：写成条件，不修。**

### 8.4 （本轮新发现）硬链接：**能放行，但性质不同**

- 脚本：同上（P-C）。
- 做法：`ln /tmp/.../target.tsv <仓库内稳定路径>`（本机 `/tmp` 与仓库同卷
  `/dev/disk3s5`，硬链接可建）。闸看的是稳定路径 → 放行，追加的字节在 `/tmp` 那个名字下
  同样可见（同一 inode，`ls -i` 两侧同号）。
- 判断：**这不是「记录丢了」**——稳定名字还在，`/tmp` 被清理也不影响 inode 存活。
  它不构成 8.1–8.3 那种失败。但它说明文档里那句「判『字节落在哪』」**对 inode 不成立**：
  一个 inode 可以有多个父目录项。已改口径，并把它列进「抓不到什么」。

### 8.5 附带确认：临时目录根解析失败时只警告并跳过（会不会被利用）

- 证据：`.pi/review-v4/evidence-tempdir-root-unresolvable.txt`。
- `TMPDIR` 指成环软链时：目标在稳定位置 → stderr 出现
  `警告：无法解析临时目录的真实路径，本条不参与判定`，**写入照常（rc=0）**；
  目标在成环的 `TMPDIR` 之下 → **rc=4**（目标路径同样解析不出来，fail-closed）。
- 判断：**不可利用**。要让某条临时根被跳过、同时把记录写进那条根之下，目标路径必然
  也解析不出来，于是先撞上退出码 4。跳过只影响「本条根不参与判定」，不会把落点洗白。
