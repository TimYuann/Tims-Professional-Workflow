## 1. gate 不可送达：按既有授权继续，不能推出新授权

采用**有范围限制的读法一**：已经获授权的可逆调查、实现、自审、自验与范围内的本地交付，可继续；不可送达不撤销已有授权，也不产生新授权。
发布、删除、迁移及其他需明确授权的动作，缺授权就停住该动作。不能把自审 fallback 当成其授权。

依据：BRIEF 的按能力 fallback、非默认硬阻塞、一次低劳动量 gate 与不反复索取许可；M2 决定要求不可送达如实记账。
另有前任在交接完整确认时明确补充（本次将其落为可冷读记录）：

> 若 Owner 通道不可达，记录 gate 未送达，不得写成 Owner 同意；已授权的可逆工作可继续自审自验并披露。发布、删除、迁移等需明确授权的动作，不能靠 fallback 越过。

这条是前任交接的解释边界，不冒充 Owner 新原话。Oracle 据上述既有方向裁定，**一次 gate 是可送达时必须履行的独立路线提供义务，不是所有已授权工作的重新授权前置条件**。
没有通道时记录义务无法履行的事实，不记成已提供、未答或 Owner 同意。只是未尝试送达、worker 自己没有直达通道，都不等于整个执行链不可送达：须先判断 Driver／Voice 或已有正常通道能否转达，不要求为此新建 runtime。

需在候选中消除 §0 与改 1／改 3 的冲突，并将以下三项分开：

- **授权**决定哪些动作可以做；缺授权阻塞对应动作。
- **独立性**决定谁作判断及披露义务；缺独立性不自动否定实际验证结果。
- **验证结果**由实际观察决定。缺 gate 不能直接推出 `A8.verdict = UNVERIFIED`；若缺授权使必要验证无法执行，才因缺实际证据记 `UNVERIFIED`。

P6 原有 `A8.verdict = PASS` 条件保留。即使验证 PASS，也不能据此发布未获授权的内容；不可送达时无法真正向接收者披露，就不宣称已完成可见交付或披露，保留本地产物与待送达事实。
通道恢复后随正常交接送达记录，不反复索取同一 fallback 许可。
