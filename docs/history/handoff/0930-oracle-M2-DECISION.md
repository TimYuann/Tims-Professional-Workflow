# 0930 · Oracle 对 M2 两问的裁定

> 输入：`0930-driver-M2-REPORT.md`、`0930-boundary1-CONFLICT.md`、`docs/history/derivation-0930/ADVERSARY-VERDICT-INDEPENDENCE.md`。这是 Oracle 根据 Owner 在本轮对话中已表达的要求作出的路由裁定，供 Driver 修订方案和 Scribe 追加 A9；它本身不替代 `workflow/registry.yaml` 的正式契约，也不是对 Driver 候选的最终实现验收。

证据锚点：Owner 的一次 gate、自审标注与三态边界见 `docs/history/handoff/0930-oracle-to-driver-BRIEF.md:14`；当前 A8 三态见 `workflow/registry.yaml:297`，P6 `PASS` 闸门见 `workflow/registry.yaml:430`；Driver 的待答两问见 `docs/history/handoff/0930-driver-M2-REPORT.md:87-100`。

## 三个词，各答一个问题

| 词 | 回答的问题 | 记录位置 |
|---|---|---|
| **验证结论** | 对目标实际跑出了什么？ | `A8.verdict`：`PASS`／`FAIL`／`UNVERIFIED` |
| **判断独立性** | 这次 A7 裁决或 A8 验证由候选作者自己完成，还是由另一位评价者完成？ | 各自的独立性字段；P4 与 P5 可合法不同 |
| **路线与 gate 结果** | 为什么走到自审？独立路线是否给过 Owner、Owner 是否配合或回应？ | 一次 A9 审计行，按候选对象和阶段关联 |

## Q1 · `independence` 保持二值，路线原因另记

`independence` 只表示**判断者与候选作者是否分离**：`独立复核`／`单会话自审`。不要把「开不出独立会话」和「开得出但 Owner 未配合／未答」做成第三个独立性取值；两者最后都可能由同一会话自审，差别在**走到此处的原因**，不是谁作了判断。

为防静默降级，Driver 在同一候选的 A9 行记录一次 gate 的动作与结果，至少区分：`独立路线不可用`、`已提供可复制启动 prompt 且 Owner 选择独立路线`、`已提供但未配合`、`已提供但未答`。未答不是同意，也不是第二次追问的理由；按 Owner 的非硬阻塞要求继续自审时，明确记录它。实现时让 `A9.subject` 指向候选身份，`evidence` 指向给出的 prompt／沟通位置，`result` 写路线结果。若现场连向 Owner 送达的通道都没有，记录不可送达与事实依据，不伪称已经完成 gate。

**A7 与 A8 不要求取值相等。** 例如独立会话做 P4、同一会话做 P5，两份产物应分别如实记录，P6 的披露条件取两者中较弱的一侧。不得为让检查变绿而强制两字段相等。

## Q2 · 用户可见交付与 A9 审计记录都要有

Owner 要求的是**交付时显著标注**，所以实际送给接收者的最终回复或交付物必须出现「未经独立复核」；只写 `A9.result` 而不显示给接收者，不算完成。A9 另外记录**交付物指针、披露发生的事实与结果**，让后来的人能追查；只有交付物散文而没有可追的审计行，下一会话无法复核这次降级。

P6 的人审判据应同时核实际交付面与 A9 行。`C4` 最多证明判据里的 `A9.result` 字段存在，**不证明交付物真的标注了**；检查输出不得声称已有机械保证。若以后能对实际交付物建立稳定的程序化读取与反例，再讨论新增检查。这里不增第十类产物。

## 不因这两问改变的闸门

独立性和运行结果是正交的。单会话真实跑过验证且满足 `A4.done_definition` 时，`A8.verdict` 可以是 `PASS`，同时标明自审。跑不出来、环境坏、证据不够仍是 `UNVERIFIED`；一次 Owner gate 不把它变成 `PASS`，也不放宽现有 P6 的 `A8.verdict = PASS` 条件。

Driver 可据此修订候选并交另一位评价者验收；不要让候选作者自己裁自己。Scribe 按 A9 只追加记录本裁定的依据和后续落地结果，不改既有台账行。
