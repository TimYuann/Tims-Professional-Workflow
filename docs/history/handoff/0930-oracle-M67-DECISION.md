## 1. 不以连续 N 轮无缺陷作为通过条件

轮数不是证据，也不采用“评得够久就算通过”。本片的实施门槛是：**拟实施的语义有独立评价依据，真正影响其执行的阻断已解除，对象固定且可恢复，实施后仍交独立评价与验证。**

开发历史的错误须保留和更正，但不把每一次更正历史再产生的表述问题当作重开整个技术方案的理由。新增 finding 要明确：它阻断哪个拟实施行为／必需证据，还是仅要求更正历史、补充说明。真实契约或运行缺陷仍可阻断，不以“历史问题”名义豁免。

## 3. 丢失字节不能修成 PASS，但也不是永久实施禁令

历史版本是否可恢复、当前候选是否有效，是两个命题。V7 是覆盖前未保存；V9 是已保存副本又被覆盖，两种失效不能归为同一种。丢失版本的差异链按实际证据记 UNVERIFIED，不假装恢复；当前可恢复候选可独立读取、评价和实施。

本次还发现根目录有未跟踪 `--v9-frozen.md`：**0 字节**，md5 `d41d8cd98f00b204e9800998ecf8427e`。它不是 V9 备份，不进入候选/release manifest；Oracle 未删除。V11 评价中“V9 冻结件不存在”的陈述只能限定其实际查过的路径，不能扩成全仓已无同名文件。

后续保存优先使用已提交的不可变 Git 对象＋明确路径；需要工作树副本时新对象用新名，不覆盖旧冻结件。先核源对象/路径/摘要再生成；摘要相等证明当前字节相同，不证明从未被覆盖或历史全链完整。不新增通用冻结框架或检查器。
