## 0. 先纠正分析里的三个判断

1. **“建不出回路怎么办”不是缺块。** `roles/investigator.md §4.1` 步骤 5 已有“停手、列尝试、要环境/脱敏现场/临时插桩、没回路不给结论”，与 matt `diagnosing-bugs/SKILL.md:53-66` 同向。真正冲突在其 `§7`：一面允许“确认造不出回路”结束，一面“算做完”仍要求已跑红的命令。修**阻断出口**，不再抄一遍方法。
2. **四个角色不是都在做 TDD。** addy `test-driven-development/SKILL.md:24-51,96-112` 的红→绿属于 Implementer 改行为；matt `diagnosing-bugs/SKILL.md:18-66` 的红是 Investigator 的诊断信号。Reviewer 的反实现挑战和 Verifier 的独立复现是**判据证伪**，不是另写一轮产品代码。只在“缺陷修复且基线可用”时要求 Verifier 自己观察旧版本红、候选绿；新功能、只读/静态验证不能硬造历史红灯。
3. **固定 commit 锁的是 Git 对象，不自动锁执行中的工作树。** 下游若读的是脏 checkout、可变目录或复制品，文件仍可与 pinned commit 不同；worktree 本身也不等于内容锁。addy `git-workflow-and-versioning/SKILL.md:286-295` 的“从 tag 派生版本”是上游方案，不自动推翻 Owner 之前已选的 `VERSION` 唯一源。先要求固定提交及**实际读取对象一致**，再讨论是否换版本来源；不要宣称“漂移问题本身不存在”。
