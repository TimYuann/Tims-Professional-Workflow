## 二、保全分层：能恢复决定，不等于保留所有现场

**下表写“至少保留到什么条件”，不是法律意义的永久期限。** “长期”意为在该决定仍约束维护/追责/后续引用时可取回，失效时保留替代关系与历史依据；法律/隐私/清理期由 Owner 决定。被上层结论引用的下层材料会**随引用升级寿命**，无权保管时只能降低结论并阻止未来复用，不能假装会一直存在。

| 档 | 什么、为什么 | 生命周期与写者；何时能丢 |
|---|---|---|
| **D：长期权威与审计骨架** | 有效授权的原文/对象/条件/时间与撤销，已接受的业务/设计裁决及旧裁决被谁替换，产品长期契约/词义（若有）、已交付对象身份、独立 review/verifier/integration **结论与其证明指针**、最终 `roundup`、承重拒绝/返工理由。缺任一项会让后来人无法解释为何交付或为何未交付。 | Owner/授权业务人**决定**业务目标；Driver 记录授权、派活、决定链和最终索引；各判断者**写自己的原始结论**，Integrator 写集成收据。保留至相应产品承诺及审计依赖终止，变更用新版本/撤销链接，不覆盖原冻结结论。**不是永久留敏感原始数据**；需要历史但含隐私时存脱敏摘要与获准的受限原始材料。 |
| **W：活跃批次/周期记录** | 未决问题与选项、进行中切片/状态、失败尝试与分叉/推翻理由、阶段性交接、可重入 checkpoint、未晋升候选和实跑输出。它们保证“当前做到哪、下一步谁接、为什么换路”；少了就不能无人值守安全续跑。 | 各产出者对**自己的产物**单写，Driver 在现有卡/索引中保持当前前沿；每个关键决定/移交/挂起**当时**落盘，不在会话末凭回忆补。批次结束时把仍承重部分提升进 D；其余在 Owner 批准的周期/项目清理规则下归档或删，不因为结果 PASS 立即清空。 |
| **E：可复用证明材料** | 能使某条结论再被核对的精确输入/环境/原始读数/夹具/命令/对象身份；原始日志可截最小有效段，保留 hash 与必要重建说明。 | 原产者记录，Reviewer/Verifier 核使用资格，Driver 核期限与权限。**只要 D/W 的结论仍以它承重，就不能把它按临时件删**；能独立重建才可由授权方保留可重建材料替代原始件。环境或对象改变按 `pipeline.md §8` 失效/重判；没有存储授权时标“仅此轮有效/未来不可复用”。现有保全规则保留，不重新设计一套。 |
| **S：可丢工作现场/派生视图** | 测试缓存、可重建 status/index、实验性未被引用的探针、临时实例/分支、重复副本、未用于决策的完整逐 token 会话流。 | 创建者只清**自己拥有且未被 D/W/E 引用**的部分；派生状态从权威记录重算；清理前核没有承重依赖。凭据/私密原始数据不因“全程记录”而无限复制；合规销毁与事件索引分开。 |

**可溯源/可分析的验收读数**：给一个离线、未见过该任务的新会话，仅凭被保留的文件/项目 tracker（不看原对话）应能回答：谁批准了什么、为何选此路、当时基线与环境是什么、哪些方案失败/被否、谁独立判断、原始证明在哪里/是否过期、现在的前沿与待谁决定。应能从 **D→W→E** 找到关键指针并核 hash/身份；找不到的主张降为 `UNVERIFIED` 或明确仅为历史事实，不伪装有效 PASS。**“全程不丢”是关键状态与决策在前进前落到可恢复介质**，非监视全部聊天。若 Owner 真要求逐条原始操作留存，需另裁隐私、成本、法律期限和存储服务，本方案不擅增。
