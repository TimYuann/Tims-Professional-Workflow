# 真实链路测试后 · 最小修复计划

**状态：计划，不是实现或验收报告。** 本轮只写此文件，不改角色、脚本、被测项目或 `/tmp` 证据。依据为 `.pi/core/FLOWTEST-REPORT.md` 及其原始 `contract.md`、`slice-plan.md`、`task-card-f-impl.md`、`EVIDENCE-RETENTION.md`、`roundup.md`；本库现行 `roles/**`、`closure.md`、`pipeline.md`、`identity.md`。原始会话工具结果支持关键对照：旧测试 × 比例变异为 `7 passed`；加非边界定额断言后比例变异为 `1 failed, 7 passed`。因此这是**一次小项目里真实工作的正例，同时暴露了验收标准和证据保存的缺口**；不能把这一例推广为所有档位/异常路径已经闭环。

## 一、先答四问（据此决定改、不改什么）

1. **谁管验收口令够不够？** Owner 管“要什么结果”，不是替工程团队设计每个反例。**Planner 对 `slice-plan.verification` 负责；没有 Planner 且条件满足时，Driver 代产完整 `slice-plan`，也接过这份责任。** 实现者先写红测试，独立 Reviewer/Verifier **仍须挑战判据**，不能因为“上游负责”就免审。原测试不够是 Driver/Planner 的**前置判据设计缺口**；审查者抓到它不是越权或“顺手帮忙”，正是独立审查的保底价值。`make check` 是运行入口，不自动等于“能识别定额与比例”。
2. **证据谁保管？** **先加一条可执行的交付纪律，不新增保管角色。** 造证据者标明对象、位置、散列、能否重建及预计保留到何时；冻结判据的人不能把未经授权且易失的 `/tmp` 路径写成长期必需前提；收件人检查可取回性；Driver 在收口时核准保留/搬迁/明确放弃。Ledger Custodian 管来源台账的生成区，不因此自动取得用户测试数据或凭据的保管权。
3. **“改 closure.md”判反了吗？** 判“**Driver 补正式主收据，而不是 Implementer 自补验收**”是对的；但**当前 `closure.md` 主链第 3 行、`roles/driver.md §3` 和 `pipeline.md §11` 已经写 Driver 代产完整 `slice-plan`**。报告里“closure 仍让 Implementer 补”与当前被审文本不一致，可能描述了较早版本；**不要为修一个已消失的句子再改 closure**。本轮的实际收据方向是正控制：若 Driver 不交，Implementer `§4.0` 应停。真正待修的是代产者给的判据够不够（第 1 问）。
4. **四条是否同一类？** 同属“**承重前提跨交接点被当成已成立，却未在使用前证明并在需要的时段保住**”：验收口令的区分力、主收据的合法生产者、身份范围的例外、冻结判据依赖的文件寿命。但它们分别涉及**判据权、产出权、范围授权、证据保管**，不能用一个泛化检查器或一份新收据包办。共用的短纪律是：**生产者说明前提与依据 → 收件人在使用前核对 → 缺/失效就退回或限缩结论 → 冻结后保持对象与证据可取回**；下列只在各自现有角色/文件补承重的一句。

以下 **3 项小改动 + 1 项只做回归不改代码**。每项都有落点、建议原文、依据、实际情景；做完仍由独立判断侧检验，不把 `check-library.py` 结构绿当交付成功。

- **影响与新洞**：多一道轻量判据设计动作，**不加角色/收据/全量变异门**。Driver/Planner 是判据生产者，Implementer 写可运行测试，Reviewer/Verifier 继续独立审查；不能让 Driver 因定义判据而给实现候选自判 PASS。

## C 批 · 按真实用户旅程复核，不扩流程

实施顺序：**A1 判据责任 → B1 确认既有 Driver 收据不被改坏 → B2 范围声明 → B3 证据保管**。每一批只改本仓获授权文件，保留已有改动；同步受影响的 `SOURCES.md` 落点/角色引用由现有 Ledger Custodian 处理。收口先走三个情景：

1. **比例错实现对照**：旧 7 条全绿不应使任务卡晋升；上游判据在开写窗前给出非边界 witness，新测试让比例实现红，正确实现绿；Reviewer 独立再挑战，不能把上游判据当终审。
2. **范围对照**：候选只含获准的两文件；具名 loops runtime 变化可在事前声明的全树比对中排除，另加一个未声明 `.pi/` 源码必须被发现；任何人不能事后改排除来获得“无越界”结论。
3. **证据寿命对照**：冻结 C9 引 `/tmp` 时立即可运行，但若无授权稳定保管，结论只能限于这次仍可取回的环境；临时证据消失后复用应失败。能重建的最小输入经 hash 核对后可按新对象重做，不把原本没保留的变异原始读数说成还在。

维护者如修改角色/契约/来源，可跑现有 `scripts/check-library.py` 与 `scripts/render-ledger.py --check` 作**结构回归**；它们**不读取本次真实任务的收据或 `/tmp` 证据**，因此不能替代以上三条情景和独立判断。完整 `full(9)`、solo、缺件退回、两轮上限、Ledger Custodian 与 Oracle 触发边**本次没有被真实链路验证**，不因这次三会话小项目 8 passed 就宣称覆盖。
