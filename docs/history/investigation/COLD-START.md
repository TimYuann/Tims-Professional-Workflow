# 冷启动 / 安装过程：待解题（Owner 2026-09-27 指示记下）

## 场景（Owner 原话推演）

在**下游仓库**（例：UCBIP）里开一个新会话，对它说：**"我要用 TIM Professional Workflow 这套东西开始开发。"**

## 问题

**这个 agent 进来之后，知不知道该把哪些东西读取出来、哪些东西拷贝走？**

具体：
- **脚本必须搬/复制到下游仓库**——不可能从上游仓直接执行。
- 安装完之后，这个 agent **事实上已经读过 UCBIP 原有的 AGENTS.md 等一系列文件**；现在要它**再去读 TIM 里对 Driver 的要求**，并**按 TIM 对 Driver、以及应用这套系统的流程**去工作。

## Owner 的定义

> **它实质上会有一个带引号的安装过程。**

## 要解决的问题（Owner 原话）

> **任何下游在克隆了我们这个仓库、或者安装了我们这个仓库之后，agent 如何消化它本地自己项目？agent 如何消化它？**

## 与已定事项的关系

- 这是 **A↔B 适配的入口环节**：安装 = 第一次做 B 盘点 + 情况判断（1/2/3）+ 建映射。
- **每个新 Driver 都必须先验证"映射表是否存在"**（Owner 定的"新 Driver 自检"）：
  - **存在** → 前面已有 Driver 用这套工作流在这个项目推进过 → 沿用；
  - **不存在** → 这是首次引入 → 走盘点与情况判断。
- **只在引入时判一次**；判完建好即可，**不需要每批重判**。

## 尚未解决

- **安装后 agent 的读取顺序**（本地治理 → TIM 对 Driver 的要求 → 项目 B 盘点 → 映射）；
- **安装动作由谁执行、谁批准**（下游仓库是别人的地盘，写权要谈）。
