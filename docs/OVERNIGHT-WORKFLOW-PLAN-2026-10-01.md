## 4. Git 与写入可逆性

开工建立本夜专用分支与干净 worktree，例如 night/2026-10-01-workflow；从计划接受后的固定 HEAD 出发，不以 dirty main 作候选。
先记录 root HEAD、index、tracked dirty 与 untracked 的身份／归属；在只读状态保全必要快照，不 reset、stash、clean、批量删除或把遗留项捆进提交。
旧八项暂存及历史在飞文件保留在原工作树。本夜不把它们当成当前接受方法或必读全集。
原工作树已有 dirty A9 不整文件混入本夜提交；本夜工作树的决定只追加，清楚记录内容作者与实际落笔者。

每个可依赖阶段交付一个范围内 checkpoint commit；作者提交保全不等于接受，评审记录指向 exact commit／tree 或固定内容摘要。
真正合入夜间交付分支的共享文件由一个具名集成写者串行处理；并行作者用独立分支／delta，不靠共写新配置真源抢顺序。
Driver 管逻辑资格，物理集成写者按已获委托落实；本夜可以 cherry-pick 自有阶段提交进入夜间分支，不 merge 到原 main。
原则／语义 owner 与物理 writer 分开，保留来源。冻结件以 Git 对象恢复，不用可覆写的“frozen”文件假装保全。

非平凡改动前有基线 commit。修错以新提交或 revert 自有提交恢复，保留评审和失败证据，不 amend／rebase／强制推送／改写公共历史。
回退到先前 prefix 后必须重新说明交付范围与资格，旧 PASS 只继承仍相同的对象与覆盖。
最终包来自已验 commit 的受控导出；manifest 固定 source commit、tree、内容文件和算法名。绝对本机路径不成为下游持久依赖。

从集成 exact commit 导出独立新包并作维护核验与运行冷启动；明确检查对象和实际覆盖。

回退演练用一个自有 checkpoint或受控副本：实际恢复旧对象、重装配并观察可工作，不把列一条 revert 命令当恢复证明。

UCBIP adaptive 准备只读现行权威，核查 CARD-STATE、role-binding、current-release、delivery contract、receipts、evidence-ledger 的对象分工。
方法权威与下游产品／权限／runtime权威分开；Integrator 保持 main 单写；新包契约在现有 packet／receipts 中有界承载，不强搬旧 A1–A9 schema，也不竞争当前状态或证据索引。
交出可采用说明／样例和最短核读清单，不替下游决定业务行为，不新增其目录、活状态或执行权限。

够格：同一固定交付对象有独立语义评价、相关真实观察、包依赖闭合、冷启动与回退证据；残余明确且没有挡住所声明采用路径。
固定 source commit＋tree＋manifest 为本地候选身份，正式 tag／发布仍待晨验决定；新包没有 tag 不伪装成已发布，也不继承旧 C1 作为实现 blocker。
新包相关方法／运行断言失败则不能交付为可用；历史库的结果不论红绿都不替代本包证据。

## 6. 自主推进、收敛与夜间停止规则

Driver 根据上项阶段资格推进；Oracle 在语义／接受里程碑裁定，不直接微派所有 worker。独立评价不接受作者自查替代。
每阶段默认一次完整独立评价，合并 findings 一次修正；只有实质差分、失败或覆盖失效再复核，不机械重复全检查。
同一阶段累计两批修正仍有 blocker时，先做一次边界／根因裁定，选择缩到仍满足目标的方案或停该依赖；不以换版本号重置问题，也不无限加轮。
缩减不能改变晨验承诺而不披露；最后可用 prefix 仅按其已验范围交付。
模型／工具故障先做有界诊断；不向睡眠中的 Owner重复问许可。保留项列到晨验，不能把未答当接受。
接近晨验只允许完成相关阻断修复、资格和包；来源扩展、机会性重构与新系统研究进入后续，不挤掉交付窗口。

本夜 closure rule：M1–M6 的必需采用路径有固定对象、独立判断与证据，冷启动／回退成立，无未处置的方法或采用阻断项，且保留边界未越过 → Oracle 接受本地采用候选，Driver记录本夜关闭。
发布身份待授权、真实 UCBIP 业务有效性未验可以作为明确剩余，但不得伪称已解决；若包不满足本地采用路径，则晨验报告必须判未完成。
“哪些 finding 阻断”按本计划所承诺路径及相关专业 authority 判断；Driver 不能自行降级 finding。

## 7. 晨验报告与交付位置

一份自包含晨验报告：目标是否达成、固定对象／包身份、当前入口、模型实际配置、六阶段结果与证据指针、失败及处置、成本读数、未验／保留动作、回退对象、下游最小采用步骤。
过程消息保持短；结论、决定与实际观察落持久产物，有条件或降级必须可见。
接受计划后为阶段结果只维护一个简短进度表，详细证据按对象引用，不把每轮聊天另开成文档族。
晨验接受后再做主线晋升与旧版归档：固定旧 commit、原 staged/dirty 的保全身份及恢复办法；旧内容退出活跃入口，原始来源与证据保留；一次切换当前入口，不留两套并行权威。
主线晋升不是把脏旧工作树强行覆盖，归档不是删除证据。该动作与夜间候选资格分开记录。
计划审阅聚焦：晨验目标是否真实可达、授权边界、阶段标准有没有变成 ceremony、固定交付对象是否够用；不重开 Backbone。
