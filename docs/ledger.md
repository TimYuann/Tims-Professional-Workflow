# 决策台账工具（A9）

`A9` 是全工作流唯一常驻的产物。`scripts/ledger.sh` 是它的追加工具。

**纪律：只追加。** 本工具没有删除和编辑功能，这是刻意的。
写错了就再追加一行说明上一行为什么错。

## 八栏：前四栏是身份

没有前四栏，多 agent 并发写下的一堆行**彼此无法区分**——台账在 swarm 场景下
就只是一堆没有归属的文本。这四栏就是为此存在的。

| 栏 | 内容 | 谁填 |
|---|---|---|
| `actor` | 谁写的。角色名 + 会话标识 | **只认 `TPW_ACTOR`**，不注入就落成 `unattributed:pid:<n>` |
| `run` | 本次运行的标识。并发追加靠它区分谁写的哪一行 | 工具从 `TPW_RUN` 读，否则按时间戳+父进程生成 |
| `subject` | 这条决策关于哪个对象：commit、文件路径或契约条目 | 调用方 |
| `phase` | 在哪个阶段做出 | 调用方 |
| `decision` | 决定了什么，动词开头 | 调用方 |
| `why` | 为什么 | 调用方 |
| `evidence` | 凭什么：文件行号、命令输出、一次运行、或 `A2` 结论的 id | 调用方 |
| `result` | 结果如何，包括「后来发现错了」 | 调用方 |

## 用法

```bash
scripts/ledger.sh <台账路径> <阶段> <对象> "决定了什么" "为什么" "凭什么" ["结果如何"]

# 例
TPW_ACTOR=builder scripts/ledger.sh .decisions/ledger.tsv P3 abc1234 \
  "把邮箱校验的错误提示从 alert 改成 inline" \
  "alert 会遮住用户正在输入的密码" \
  "实跑截图：输入密码时 alert 弹出导致输入中断" \
  "已上线，下一轮补 a11y 复查"
```

**多 agent 并发时每个 agent 必须注入自己的 `TPW_ACTOR`**，否则并发写出来的行
**全部落成 `unattributed:pid:<n>`**——台账还在写，但归因不到人，等于记了个空。

> **为什么只认 `TPW_ACTOR`，不读别的环境变量**：这个库自称工具解耦。
> 在脚本里读一个以某个具体工具命名的变量，就是把那个工具写进了契约——
> 换套工具就静默失效，而静默失效在台账里长成「actor 栏都是空的」，
> 没有人会去查为什么。需要会话标识就注入 `TPW_RUN`，不注入就退到进程号，
> **并且让它写成 `unattributed:` 开头，一眼能看出这一行没归因。**
无法归因。工具不会替你猜。

## 并发安全

实测过的机制，不是设想的：

1. 用 `mkdir` 拿锁（POSIX 保证原子性）。**不用 `flock`**——macOS 默认没有；
   **不用 `shlock`**——各系统参数语义不一致，本机上 `shlock -p $$ -f file`
   会静默失败。
2. 拆僵尸锁前**必须重读持有者确认没被别人接管**。
3. 退出释放锁前**必须确认锁还是自己的**。
4. 追加用 `exec 7>>`（`O_APPEND`）在已打开的句柄上写，
   即使锁因故失效也没有人会用 `>` 截断已有行。

前三条是踩过坑才写进去的：最初版本把「循环次数」当秒数，
60 个并发时锁在 1.5 秒后被抢走；改成真实秒数后又因为退出时无条件
`rm -rf` 删掉了后来者的锁。**这两种故障在 60 并发下 20/20 轮复现。**

### 已验证到什么程度

| 场景 | 结果 |
|---|---|
| 40 轮 × 60 并发首次追加 | 0 丢行、0 表头重复、0 列数错乱 |
| 10 轮 × 150 并发首次追加 | 0 丢行、0 表头重复、0 列数错乱 |
| 不同 `TPW_ACTOR` 并发 | 三种 actor 全部可区分 |
| 持锁进程已死的僵尸锁 | 能自愈并正常写入 |
| 写入临时目录 | 拒绝（退出码 3） |

**未验证**：网络文件系统、进程被 `SIGKILL` 后 120 秒内的极端时序、
以及本机以外的文件系统。落在下游项目上时要重跑一遍并发夹具。

## 它不做的事

- 不判断一条决策该不该记。
- 不检查 `evidence` 是否真实存在。**这一条只能靠写的人自觉，所以复核台账时必须抽查。**
- 不做任何汇总、统计、格式化。台账是原始材料，不是看板。
- 不写入临时目录。**需要留档的东西落在临时目录等于没写。**
