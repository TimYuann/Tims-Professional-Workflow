# 集合 A · 工作流的全部产物

一个**产物**不是一份文件，是「一组字段 + 谁产出 + 谁消费 + 活多久」。
它落在下游仓库的哪个路径，由 `driver` 按集合 B 裁定——
纪律是本库的，位置是下游的。见 [下游映射](downstream-mapping.md)。

## 字段

### A1 · 诉求陈述

- `ask` — 要解决什么，写成第三方能原样复述的一句话
- `done_meaning` — 做完之后世界什么样——不是「做完了」，是可观察的差别
- `non_goals` — 明确不做什么。空着等于没想清楚
- `unknowns` — 现在还不知道的，以及它挡住了哪一步

### A2 · 事实集

- `claims` — 每条结论 + 置信档位：直接（有人明确写了为什么）／推断／未验
- `evidence` — 对应锚点：文件行号、命令输出、或一次真实运行
- `gaps` — 查过但没查到的——写清在哪里、用什么关键词查的

### A3 · 能力地图

- `capabilities` — 系统对外提供哪些能力，每条挂到真实代码锚点
- `consumers` — 每条能力谁在用；没有消费者的能力是候选删除项
- `freshness` — 上次与代码核对的时间。过期不更新的地图比没有地图更坏

### A4 · 冻结契约

- `what` — 建什么。动词开头，能被第三方复述
- `why` — 为什么——业务理由，不是技术偏好
- `done_definition` — 什么证据算完成。必须可判定：只凭它能给出 PASS/FAIL/UNVERIFIED
- `boundaries` — 什么不做、什么不许改——包括不许为了变绿而削弱检查

### A5 · 任务图

- `slices` — 每一片的边界；判据是「能不能独立验证」
- `edges` — 依赖边。有边才能并行，没验收口径的并行结果无法汇合
- `acceptance` — 每片的验收口径，必须能追溯到 A4.done_definition。外来项例外：它的验收口径追溯到条目自身声明的行为

### A6 · 实现候选

- `change` — 改了什么
- `runnable` — 怎么把它跑起来——真的能跑，不是「应该能跑」
- `known_gaps` — 知道自己没做什么。这一栏非空才有资格交给别人评价

### A7 · 裁决

- `stance` — 采纳／挑战／附条件通过
- `reason` — 为什么。必须指向 A2 的证据或一次真实运行；「感觉不对」不是理由
- `conditions` — 附条件通过时，条件是什么、由谁验收

### A8 · 验证凭据

- `claim` — 证明了哪一条 A4.done_definition
- `observation` — 实际观察到什么——跑出来的，不是推理出来的
- `environment` — 在什么环境、什么对象上跑的
- `verdict` — PASS／FAIL／UNVERIFIED。环境故障既不算 PASS，也不得直接判成产品缺陷

### A9 · 决策台账

- `decision` — 决定做什么
- `why` — 为什么
- `evidence` — 凭什么
- `result` — 结果如何

## 三条不可协商的落盘纪律

1. **`persistent` 的产物必须有可追溯的落点。** 找不到位置就问 Owner，不要塞进临时目录——丢掉的记录等于没做过。
2. **`session` 级的产物不进版本库。** 它是判断的输入，不是交付物。
3. **台账只追加。** 不修改、不删除既有行。写错了就再写一行说明为什么错。
