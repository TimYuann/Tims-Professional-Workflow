# 会话移交

> 把当前状态压成一份让下一个会话能接手的东西；并从复盘里回写经验。

- 阶段：横切带　归属角色：`scribe`　产物：A2

## 什么时候用

- 接手别人的活：新的会话、新的执行者，先要一份「现在到哪了」。
- 交出去之前：自己要去别处，或这一轮结束，必须留下一份能被接手的东西而不是「我说过了」。
- 一个决策做完了，回看它值不值得留下：把这次的做法或踩坑编码进结构，而不是留在某人的记忆里。

## 开工前要拿到

- **A9 决策台账**（`inputs` 里唯一的产物）：它是这次移交的事实底座。台账取不到，就只剩下一段叙述，移交的置信度整体降一档——**此时不要凭印象补**，把「无台账可依」写进 `gaps` 本身。
- **A1.ask 与 A1.non_goals**：接手的人要知道自己在往哪个诉求上收敛、以及哪些方向是明确不做的。拿不到就把这一步标 `UNVERIFIED`，并点名缺 A1 的谁。

## 方法

上半段——**重建**：

1. **锁范围再查**。先定死这次要看什么：哪一段时间、哪个主题、哪个对象。「最近」是一个范围，不是一句形容词；把范围写回去再开始查。
2. **从 A9 读判断，从活的状态读事实**。台账给出「为什么」，当前代码、分支、未合入的改动给出「现在是什么样」。两边不一致的地方单列——那通常是一个还没被记下来的发现。
3. **在活状态上核一遍**。台账里出现的对象，逐个确认它还在原地、还是已经被别人改掉。核不上的是 `gaps`，不是可以略过的细节。
4. **空结果也是结果**。查过但没查到的，写清在哪儿查的、用什么关键词、结论是「没找到」。沉默会被下一个接手的人读成「不存在」。

下半段——**回写**：

5. **分清哪些值得回写**。一次性的处置不值得；同一类问题第二次出现、或者一条纠正会跨人跨轮次生效，才值得。
6. **先问能不能变成检查**。能变成一条可执行检查、一次 lint、一条流水线规则或一个标记的，优先变成结构——它比任何说明都更不会被人跳过。变不成检查的经验才留在文字里。
7. **改动前给 Owner 看**。回写会改变所有后来者拿到的说明，属于影响面超出本轮的决定。给一份「采纳 / 不采纳 / 待议」三栏的清单，由人挑；不要自己批量落。
8. **落进产物，而不是落进某一轮**。经验回写完成后，在 A9 补一行，记下改了什么、为什么、指针在哪。

## 产出

A2 事实集。移交件用它的三个字段，缺一不可：

- `claims` — 一条一条结论，每条带置信档位：直接（有人明确写了为什么）／推断（我这么认为，但没查实）／未验（还没查）。
- `evidence` — 每条结论的锚点：文件与行、一次真实运行的输出、或 A9 里的具体行。没有锚点的结论降级为推断。
- `gaps` — 查过但没查到的：查了哪儿、用的什么关键词、结论是什么。**这一栏为空必须写成「已查全，附查法」，不能留白。**

另外附一份接手用的短摘要：整体到哪了、几条线索各自的状态、反复出现的问题、下一步最该做的一件事。它是 A2 的读法，不是新的一种产物。

## 常见做错

- **凭印象重写**。不看 A9 就总结，产出的是一段读起来顺、但每句都无法追溯的叙述。正确是先读台账，再去活状态里核。
- **把「没人提过」写成「不存在」**。查不到就写查不到，包括查法；把空结果并进结论，下一轮会在这个空缺上重新踩一遍。
- **回写时自说自话直接落**。改说明、改规则、改检查影响的是所有后来者，Owner 没点头就落，等于用一次单方面决定换掉了别人的入口。
- **把经验只写成提醒**。「下次注意」对下一个执行者没有约束力。正确是判断它能不能变成一条检查，能就变成检查。
