# 简化

> 为清晰而简化：删冗余、合并分支、去掉多余抽象。

- 阶段：P3　归属角色：`builder`　产物：A6

## 什么时候用

- 功能已经能跑、测试也过了，但实现比它需要的重。
- 评审里被指出可读性或复杂度问题。
- 遇到嵌套太深、函数太长、名字看不懂的代码。
- 在赶工压力下写的代码，现在要收拾。
- 散落在几个文件里的同一条逻辑，要并到一处。

不适用：代码本来就干净易读（别为了简化而简化）；你还没看懂它做什么；更简的版本在热路径上会明显更慢；你正要整个重写这个模块（简化一次性的代码是白费力气）。

## 开工前要拿到

- 实现候选 A6：简化是拿一份已经有形状的东西来改，前提是知道它该保持什么行为、怎么跑起来、还差什么。
- **拿不到 A6 就退回**：不知道现有行为边界的简化会顺手改掉行为，而那正是这类工作最容易出的事故。
- 先确认 `runnable` 里的验证步骤是能跑的——它是你每次改动之后的反馈信号。

## 方法

1. **先看明白再动手。** 动任何东西之前回答：这段代码负责什么、谁调它、它调谁、有哪些边界情况和错误路径、有没有测试定义了它的预期行为、当初为什么这么写（性能？平台约束？历史原因？）。答不上来就还不到动手的时候。看见路中间一道栅栏，不明白它为什么在那里，就别拆。
2. **行为一点不许变。** 所有输入、输出、副作用、错误行为、边界情况都必须完全一致。每次改动前问三句：每个输入都还是同样的输出吗、错误行为一样吗、副作用和顺序一样吗、**已有测试能不改就过吗**。有一句答不上来，这个简化就不做。
3. **顺着项目的约定走。** 简化是让代码更贴这个代码库，不是把外部偏好搬进来。先读项目自己的约定文件，再看邻近代码怎么处理同类问题：导入顺序、模块形式、函数声明风格、命名、错误处理写法、类型标注的深度。改完之后与项目约定不一致的，那不叫简化，叫制造变动。
4. **清楚优先于聪明。** 需要停下来在脑子里过一遍才读得懂的写法，不如写得啰嗦一点的写法。密集的三元链、塞在归约里的内联逻辑，都展开成有名字的中间步骤。
5. **按具体信号找机会，不按「说不上哪里怪」。** 结构上：三层以上嵌套、五十行以上承担多件事的函数、嵌套三元、布尔开关参数（`doThing(true, false, true)`）、同一个判断重复出现在多处。命名与可读性上：`data`、`result`、`temp` 这种名字；表意缩写；名不副实（叫 `get` 却改了状态）；解释「是什么」的注释（代码本身已经说了）——删；解释「为什么」的注释——留，它承载了代码表达不了的意思。冗余上：重复出现的同段逻辑、够不到的死分支与没用的变量、没有价值的包装层、给一个实现套工厂再套策略这种过度设计、已经是推导结果还要再断言一次的类型标注。
6. **一次一处，改完就跑测试。** 改一处 → 跑测试 → 绿了就提交或继续 → 不绿就撤掉这一处重新想。把好几处简化堆进一次没跑过测试的改动里，出问题时你不知道是哪一处造成的。**重构的提交和特性／缺陷修复的提交分开**：一个提交里同时有重构和特性，那是两个提交。
7. **大规模机械改动交给工具。** 超过大约五百行的重写，写脚本批量改（按文本模式替换、结构化转换），不要手工逐处改——那个体量下手工既容易错也没法审。
8. **最后回头看整体。** 比对前后：真的更好懂了吗、有没有引入与代码库不一致的新写法、diff 干净可审吗、同事会认可它是净改进吗。**任何一条答「否」，就撤回去。**不是每次简化尝试都成功。

## 产出

落到 A6（就地更新这份候选）：

- `change`：逐条列出做了哪些简化，以及每一条「行为保持一致」的判据为什么成立。合格的判据是这份 diff 里**没有一个测试被改过**——只要有一个测试为了让它通过而改了，就是改了行为，不叫简化。
- `runnable`：跑过的真实验证记录：已有测试全绿、构建无新增告警、格式与静态检查通过。**简化后没跑过验证的 `runnable` 不合格。**
- `known_gaps`：本轮**没动**的相邻问题——你看到了但决定不碰的：别处的复杂度、还没合并的重复、命名仍不理想的地方。逐条写清位置与为什么留到以后。

- **`subject`**：**候选的对象身份**——开工时的基线 commit，交付时的结果 commit。`P5` 验证的对象必须与它逐字一致。这一栏空着，下游证明不了「验证过的就是上线的」。**每个产出 `A6` 的技能都要在交付时填上它**。

## 常见做错

- 为了变短而变短：一行的嵌套三元不比五行的条件分支简单。目标是读懂的速度，不是行数。
- 在还没读懂的地方做「显然」的重写：那道栅栏多半有理由。查清当初的上下文，再决定它是否还成立。
- 顺手把不相干的代码也简化了：diff 里混进与本任务无关的改动，评审看不出本轮做了什么，回滚时被迫连坐。
- 因为「看起来更干净」就删掉错误处理：错误处理不是噪声，删它等于把故障变成静默的错误数据。
- 简化到比原来还难读：把两段简单逻辑合成一段复杂逻辑、把给概念命名的那个小函数内联掉，都是把可读性换成了行数。撤回去。
