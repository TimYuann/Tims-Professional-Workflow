# Decision Grilling · 意图对齐与决策梳理技能

## 概述
当任务需求存在模糊歧义、涉及多方取舍，或进入新领域前需要对齐认知时，调用本技能。融合了 Matt Pocock 的决策树 frontier 分轮推进法与 Addy Osmani 的附带假设提问法，**杜绝无休止的闲聊和把代码已有事实当成问题去烦人类**。

## 核心操作规程（Process）

### 步骤 1：事实自查与决策隔离（Facts vs Decisions）
在向人类提问前，必须先进行环境与代码自查：
- **凡是代码库、配置文件、Git 提交记录或已有文档能回答的事实**：自主阅读并记录，**严禁向人类提问！**
- **只有真正涉及业务权衡、产品取舍、可接受损失的问题**：才被归入“决策树”待决清单。

### 步骤 2：识别当前 Frontier（按轮次推进）
- 映射决策拓扑，找出所有前置前提已经明确的问题集合（即当前轮次的 **Frontier**）；
- 每轮只集中处理属于当前 Frontier 的关键决策，前序未定之前不提衍生问题。

### 步骤 3：附带假设提问（Guess-Attached Questioning）
向人类提问时，绝不抛出没有选项的空泛大问题（如“你希望怎么做？”）：
- 提问结构：
  1. 当前待决的核心决策是什么；
  2. 为什么需要这个决策（上下文）；
  3. **附带我们根据当前理解推测出的默认选项（置信度约 30%）**；
  4. 让人类通过确认或快速反驳来推进。

### 步骤 4：显式确认门与决策卡固化（Explicit YES Gate）
- 必须得到人类明确的肯定确认（“是 / 就这么办”）后，该决策才算 Settled；
- 输出结构化《决策卡（Decision Record）》，记录已确认事实、人类拍板选项、排除路径。

## 反借口与典型红线（Common Rationalizations & Red Flags）

| 典型借口 / 行为偏差 | 严厉反驳与纠偏纪律 |
| :--- | :--- |
| “我不知道数据库密码放哪，去问人类吧” | **禁止！** 先翻 `.env.example` 和配置文件，找不到再报环境缺口，不许拿事实当决策问。 |
| “既然用户没明确说，我就替他挑个最复杂的方案吧” | **禁止！** 涉及架构方向的大取舍必须抛出默认推测让人类拍板，不可暗度陈仓。 |
| “我们聊得挺投机，就算对齐完成了” | **没有白纸黑字就不算对齐！** 必须沉淀出包含 Settled Decisions 的决策卡。 |

## 退出判据（Exit Criteria）
- [ ] 决策树当前 Frontier 问题全部获得明确裁决（或移交 Oracle 仲裁）；
- [ ] 产出结构化决策卡，包含已冻结的硬契约与边界。
