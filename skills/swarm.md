# 并行扇出

> 扇出 N 个并行工人，排干后汇成一份报告。

- 阶段：P4　归属角色：`adversary`　产物：A7

## 什么时候用

- 覆盖面本身是一个问题：一个变更牵涉多个面（多条调用链、多个入口、多个适配层），一个人顺着一口气读必然漏面。
- 同一个怀疑需要多个独立位置同时去撞：并行跑同一份检查单，比一个人跑三遍更容易撞出不同结论。
- 两类混着来：一部分工人切分覆盖面，另一部分工人对同一份检查单各跑一遍。
- 反过来：单点深挖、上下文链条很长的问题不适合扇出——链条一断，看不见自己漏了什么。

## 开工前要拿到

- **A5（任务图）**：切片的边界与依赖边。没有 A5 就退回：切不出片的活，不该扇出——它会变成 N 份互相覆盖的猜测。
- 拿不到就退回，并把「未扇出的原因」记在 A7 的 reason 里。

## 方法

1. **框定。** 四件事写清楚：这次扇出的完成判据是什么、要交回的制品或报告是什么；形状（切分覆盖 / 同一份检查单并行赛跑 / 混用；赛跑与混用要**事先**声明取胜规则：第一轮通过的、全部排名的、还是择优）；工人总数 N；每个工人若要验证或测量，指名它要看的确切提交身份，以及测量的方法（样本数、一次样本是什么、先后顺序）。
2. **派工。** 一次性把所有工人发出去。每一份工单都必须**自足**：目标、范围、它那一片或那一条赛跑分支、怎么验证、要报什么。依赖工单的工人不能假设「上一个工人会留下什么」——上一轮的结果是数据，不是既有事实。
3. **工单里的报告格式。** 统一为三态：证据支持的通过、附证据的问题、阻断（前置条件没满足）。能证明缺陷的工人要**报出它能证明的每一条**，不是发现第一条就收工。
4. **排干。** 读每个工人的终态。缺了工单里点名的提交身份或测量方法的，直接丢弃并重跑该工人一次；第二次仍缺，记成缺口。
5. **缺口不等于通过。** 缺口按未覆盖计入，形状是「齐」时它会让「齐」不成立；形状是「赛跑」时它按事先声明的取胜规则处理。缺口的成因要写出来（跑挂了、前置没满足、范围没定清）。
6. **汇成一份。** 输出一张紧凑的结果表、每条问题一行并带证据、以及显式的缺口与掉线清单。不要把工人的原始输出整段粘回来——汇总报告的价值在于一眼看完。

## 产出

产出 **A7（裁决）**：

- **`stance`**：采纳／挑战／附条件通过，判的是这一轮扇出所覆盖的那个整体。有一处未覆盖的缺口就不能无条件采纳；缺口决定它是「附条件通过」还是「挑战」。
- **`reason`**：逐条指向工人报出的证据（哪次运行、哪次观察、哪处代码锚点）以及 A5 里对应的片与验收口径。表格本身不是理由；每一行都要能回答「凭什么这么说」。
- **`conditions`**：写清哪几片要补跑、谁去补、补跑要交回什么；以及赛跑形态下胜出者的选择依据和落选者的处理方式。

报告里必须显式出现三样东西：结果表、每条问题的一行证据、缺口与掉线清单。用了赛跑规则就把它写出来。

## 常见做错

- **工单写得依赖上下文。** 「照刚才的分析继续」这类句子让工人只能靠猜，猜错的地方会以「已覆盖」的假象回报。
- **发现第一条问题就收工。** 一个工人只报它先撞上的那条，剩下的缺陷被整体判成通过。
- **把缺口的工人的结果当通过计入。** 缺口必须显式列出；把它算进「都跑了」是最容易发生也最贵的一种误报。
- **事后才定取胜规则。** 「看哪份更好」在赛跑结束后说，等于把规则换成了自己偏好。
- **把工人的原始输出堆进报告。** 汇总报告是给人做判断用的，不是存档用的；证据被埋在几百行日志里就等于没有。
