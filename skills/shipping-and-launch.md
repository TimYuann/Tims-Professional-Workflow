# 发布

> 把已验证的变更推到用户面前，并留好回滚路径。

- 阶段：P6　归属角色：`verifier`　产物：无

## 什么时候用

- 变更第一次到达真实用户：功能上线、对用户可见的改动、数据或基础设施迁移。
- 开测试通道或早期体验通道。
- 任何带风险的部署——也就是全部部署。

## 开工前要拿到

- **A8（验证凭据）**：它证明的每一条 `done_definition` 的判定，以及哪些主张还是 UNVERIFIED。发布不需要把 UNVERIFIED 都清零，但要知道它们是哪几条。
- 拿不到就退回，并写明本轮不发布。一个没有凭据的发布，等于把未验证的东西推给用户。

## 方法

1. **发布前的清单按五面过一遍。** **质量**：检查全过、构建无警告、静态检查与类型检查过、变更已被独立评过、没有本该清掉的临时标记、生产代码里没有调试输出。**安全**：无凭据入库、依赖审计没有未处置的高危、对外入口有输入校验、鉴权与授权到位、安全头与跨域策略按具体来源配好、鉴权接口有限流。**性能**：关键指标达标、关键路径上没有逐条查询、图片有尺寸与响应式规格、关键查询有索引、热点有缓存。**无障碍**：键盘可达、朗读能传出结构、对比度达标、弹层焦点正确、错误提示与字段关联。**运维**：生产环境配置有代码来源、迁移已就绪或可执行、健康检查端点存在并有响应、错误上报在流。清单不通过的项要么修，要么显式写明「带着它发」的理由与承担者。
2. **把部署与开关分开。** 用功能开关让代码先上线但不生效，发布变成可分档推进的事情。开关的生命周期：带关上线 → 只对内部开 → 小比例 → 全量 → 清理开关和它那条死代码路径。每个开关有主人和到期日；不嵌套开关（组合数会指数增长）；两种状态都要验。
3. **分档推进，每一档都设判据。** 顺序是：预发全量跑一遍 + 关键路径手工点一遍 → 生产上代码但开关关着，确认部署成功且没有新增错误类型 → 只对内部开，盯一段时间 → 小比例（5%）并与基线比 → 逐步放大（25% → 50% → 100%），每一步都能一键退回上一档。判据提前定死，别到时候现议：错误率、P95 延迟、客户端报错率、业务指标，各给「推进 / 暂停排查 / 回滚」三档阈值。放量期的预算消耗速率异常也算暂停信号——即使各项当前值都还绿。
4. **触发回滚的条件事先写下来。** 错误率超基线多少、延迟超基线多少、用户反馈突增、数据完整性出问题、发现安全问题——满足其一立即回滚，不开会讨论。
5. **回滚路径在发布之前就要能执行。** 写下：触发条件、步骤（关开关 / 部署上一版本 / 数据迁移怎么退回）、每一步要多久、谁执行、回滚后怎么确认。**发布前试过一次**（能空跑就空跑）。一份没被演练过的回滚计划不是回滚计划。
6. **发布后第一小时盯着。** 健康端点返回正常、错误看板上没有新错误类型、延迟没有回归、关键用户路径手工点一遍、日志在流且可读、回滚手段仍然可用。
7. **看错误预算。** 预算是「你允许坏掉的那部分」，用它当客观闸门而不是谈判筹码：还剩两成以上正常发；剩两成到零只放慢节奏、不做高风险变更；耗尽就冻结功能工作、只做可靠性。每个有消费者的服务都要有这条策略，并写明降到两成和耗尽时分别做什么。
8. **别在没人值班的时候发。** 发布的目的是「出事时有人能立刻处理」，没有人在场时发布，这个目的就不成立。

## 产出

本技能不产出 A8 类的凭据；它交付的是发布记录，随决策台账一起留存：

- 发布对象：候选身份、上线的范围与版本。
- 事前清单结果：哪些面全过、哪些项是带着理由发的（写清理由与承担者）。
- 推进档位与时间：每档观察了多久、观察了哪几项、判据读数。
- **回滚路径**：触发条件、步骤、预计耗时、执行人、演练结论。这一项是阶段退出判据之一，未写下并被确认可执行就不算发布完成。
- 上线后的可观测项清单：哪几条指标/告警在盯、由谁在盯、异常时按什么流程走。
- 事后记录：最后停在哪个档位、遗留开关与到期日、发现的问题及其去向。

## 常见做错

- **没有回滚计划就发。** 这是发布里唯一不可补的一步：出事时现写回滚方案的人，同时还在处理故障。
- **回滚计划写完没演练。** 步骤里往往藏着「其实不成立」的假设——迁移到底能不能退、上一个版本还在不在。
- **开关永远不清。** 留着的开关连同它那条死分支一起变成永久负担；到期日必须当场写下来。
- **一把全量。** 没有分档就失去了「只在 5% 的人身上发现问题」这一档。
- **只看当前错误率不看预算消耗速率。** 当前值全绿但烧得比基线快，事故已经在路上。
- **拿「预发跑过了」当发布依据。** 预发的数据量、流量形态和边界情况都和生产不同；分档与盯盘才是发布的一部分。
- **发完就散。** 第一小时没人盯的话，观测数据告诉你出问题时通常已经晚了一步。
