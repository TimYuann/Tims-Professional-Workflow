# 上下文重建

> 从历史会话、活状态和共享记录里重建自己最近的工作上下文。

- 阶段：P0　归属角色：`scout`　产物：A2

## 什么时候用

- 开工前或续上一次被切断的工作，而上一次留下的东西只有一句「上次在做 X」。
- 有人问「我最近在忙什么」「上次那个进展到哪了」「我们上次停在哪」。
- 接手一个别处留下的、代码还是那个代码但进度不明的工作面。
- 记忆里只有结论，记不清结论是怎么来的、当时否掉了什么。

## 开工前要拿到

- A9 决策台账。**台账是这次重建的骨架**：它给你「做了什么、为什么」，
  剩下三份记录给你「实际发生了什么」。
- **拿不到 A9 就退回**。没有台账，重建出来的是一份「看起来像现状」的印象，
  里面每一句都可能是猜的。退回时交回的是「这个工作面没有可重建的记录」。
- 如果提问的人已经给了一份完整的状态摘要（路径、分支、改动），**直接用它**，不要再挖一遍。

## 方法

你的上下文住在**两份**记录里，两份都要读。

- **自己的历史记录**：你做过什么、定过什么。
- **共享记录**：同一片代码周围以别的名义发生的事——用户反复报的症状、
  上过又回滚的修复、线上还在冒的同一个报错。**这条尾巴最长的东西，其故事大半在这里，
  只从自己的会话里重建一定会漏掉它。** 共享记录要翻版本控制、问题追踪、讨论频道与文档、错误追踪。

1. **先分类再动手。** 目标是「重新进入一个工作面」，不是「续某一个特定的会话」，
  也不是「把一段习惯固化成流程」，更不是「写一份工作总结」。分类错了，后面的检索全是白做。
2. **先圈范围，再检索。** 定死三件事：时间窗（「最近」是一个真实区间，默认近七天）、
  主题（如果点了名）、工作区（默认当前这一个；**没被要求就不要去读别的项目**）。把范围说出来。
   **「全部」永远不等于「最近 N 天」。**
3. **分片读自己的历史。** 语料大的话按片并行：每片先搜关键词，只读命中的会话，
   只读其中相关的段落，跳过当前会话和明显的噪声（子会话、评测、测试）。
   排序按真实修改时间，不按会话标识的名字——按标识排序会让你读到最旧的而不是最新的。
   每片回一份统一形状的结构化摘要：主题、提问的人的目标、做过的决定、开着的线、
   挣扎过和被纠正过的地方、产物（合并请求、票据、分支），每条挂会话标识。
   原始记录留在分片里，主上下文只接摘要。
4. **主题一旦点了名，就去扫共享记录。** 这是默认动作，不是一次判断；
   「我最近在弄 X」不构成豁免。提问要改成：**当前状态是什么、试过什么没站住、用户还在报什么**——
   而不是「当初为什么这么设计」。
5. **回到活状态上核对。** 分片和共享记录里捞出来的合并请求、分支、票据，拿工具逐个查现状。
   答案取决于某个执行过程实际做了什么的时候，读完整记录，不要读你自己裁剪过的摘要。
6. **写出来。** 按下面的形状交付。写得紧，只讲当前状态和下一步，细节能砍就砍。

## 产出

A2 事实集。这一次的 A2 是一次工作面快照，形状固定：

- **胶囊**：最多 5 条。这件事是什么、整体处在什么位置。
- **线索**：每条线一行，每行**必须**以一个状态标签开头——
  已合并（在的合并请求号）、评审中（合并请求号）、在飞（分支名）、已验证未提交、已回滚（合并请求号）、计划中未开始。
  **没有标签的行等于还没写完。**
- **反复出现的问题**（最多 5 条）：**用户反复报的症状、以及上过又被回滚的修复要单独列出来**，
  让下一次尝试从上次失败的地方接着来，而不是从同一个坑重新掉一次。
  **这不是 `A2.gaps`**——那份 `gaps` 记的是「查过但没查到的」，两边同名不同义，不要混用。
- `evidence`：每条结论挂来源——历史发现挂会话标识，共享记录发现挂它的出处（合并请求号、票据号、错误追踪条目）。
- **下一步**：一个具体的、最有用的下一动作。

相邻的特性或票据一律不写进来，除非它挡着这一件。胶囊和线索超过一屏，**砍细节，不砍线索**。

## 常见做错

- 只读自己的历史：那条长着 bug 尾巴的工作线，故事大半在共享记录里，
  只从会话重建会把「试过并失败了」的那一段整段丢掉，于是下次重犯同一个错。
- 范围滑落：本来要重建这一个工作面，检索时顺手读了整个项目，最后交出一份没人要的全景介绍。
- 按会话标识的名字排序：那是随机串，按它排会让你先读最旧的一段。
- 线索不写状态标签：下游拿到的是一份没有结论的流水。「大概在进行中」不是状态。
- 把这一轮当工作总结写：交付的是「现在站在哪、下一步动哪里」，不是「我这段时间干了什么」。
