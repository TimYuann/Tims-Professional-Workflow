# 写给 agent 看

> 写指令、触发描述与项目约束时的写法。

- 阶段：横切带　归属角色：`driver`　产物：无

## 什么时候用

- 写一段给执行者读、并且希望它每次都按同一套流程走的文字：技能说明、触发描述、项目约束、一份被指针引用的文档。
- 一段说明写完了，执行者每次跑的路径都不一样——说明它有措辞在制造方差。
- 每次都从头解释同一件事：这些重复正在烧掉常驻的注意力预算。

## 开工前要拿到

本技能的 `inputs` 为空——它是写作规范。开工前要确定两件事：

- **这段文字由谁来读、什么时候读**。常驻加载的（每轮都在上下文里）与指针触发的（被引到才读）成本完全不同；写法跟着这个答案走。
- **这份文字要保证什么**。是保证流程一致（执行者每次做同一套动作），还是保证内容正确（读了就知道事实）。两者衡量的东西不一样。

## 方法

1. **先认清两个预算**。**上下文开销**：每轮都在上下文里的文字花的是执行者的注意力和篇幅，无论它这一轮用没用上。**认知开销**：花在读的人身上——有哪些文档、什么时候该去看哪一份。认知开销不是要消灭的东西，它是人的判断力的价格；该花的地方花，不该花的地方砍。
2. **指针决定会不会被读到**。指针指的是「一句指明外面有什么材料的引用」。**决定到达率的是指针的措辞，不是它的目标**。一份该被读的材料挂在一个措辞含糊的指针后面，是一个方差缺陷：先把措辞改利落，改利落了还不够才考虑内联。
3. **写指针的三个动作**。前置触发词（触发是在这个词上发生的）；一个分支一个触发（同一件事换个说法写两遍不叫两个分支）；砍掉正文已经给过的身份信息（指针每轮的花费是常驻的，砍得比正文更狠）。
4. **给每段内容定级**。一级是正文里的步骤——执行者按顺序做的事；二级是正文里的参考资料——按需查的规则与事实；三级是被推到外面、靠指针到达的参考资料。分支是最好用的分界测试：**每条分支都要用的内联，只有部分分支才用的推出去。**推得太少，顶部撑爆；推得太多，真正需要的被藏起来了。
5. **给同一条内容的各部分放在一起**。一个概念的定义、规则、注意事项放在同一个标题下，不要散落——读一段能把邻居一起带进来。散落和重复不一样：散落是把一个意思拆成碎片，重复是把一个意思放了两份。
6. **每步给一个完成判据**。判据有两个性质：**清楚**——执行者分得清做完和没做完（「理解了」这种模糊边界会诱发抢跑，前面的步骤还没做完注意力就已经滑向「做完了」）；**要求高**——「产出一份变更清单」推不出工作量，「每一个改动的模型都要交代清楚」推得出来。最强的判据是既可核查又穷尽。
7. **分岔只在能省钱时切**。按顺序切：一串步骤里，后面的步骤在催着它抢跑时把它们挪走；反过来，把两串顺序合并会让后一段看见前一段的收尾，同样诱发抢跑。
8. **用领起词，不靠否定**。领起词是执行者思考时本来就在用的那个概念，重复出现会积累出分布式定义，把一整片行为锚在最短的篇幅里；自己造的词不借用任何已有直觉，得不偿失，先找现成的。**否定是它旁边那个失败模式**：靠禁止来引导，等于把被禁的行为叫到上下文里、更显眼。写成正面目标（「写一行的注释」），被禁的那件事根本不会被说出来。否定只留给无法正面表述的硬红线，而且要配一个正面目标。
9. **砍**。每个意思只留一个正本——改行为就是改一处。环境本身就是正本（配置、目录结构、命令的用法说明），文档重述环境只是**缓存**：缓存只值得留那些查起来贵的——不成文的约定、某个选择的理由、某个坑。查一眼就有的（一个文件、一个命令）交给环境，它不会过期。逐行问还有没有必要；没必要的整句删掉，不要修辞。留着陈年沉积比新写更难清理。

## 产出

无产物——它改变的是判断，不是文件。

它改变的是写出来的文字本身：哪些该常驻、哪些该推出去、每一步的完成判据清不清楚。判定它做完了的标准：把每一行拿出来问「删掉它，执行者的行为会变吗」，答不出「会变」的行都删掉；再反过来问每一处该被读到的地方，指针的措辞能不能让人从措辞判断出「现在该去读」。

## 常见做错

- **先内联，实在不行再想措辞**。顺序反了。内联的代价每轮都在付，措辞是免费的——先把指针写利落。
- **一个分支写两个触发词**。看起来是在提高命中率，实际上执行者读到两个近义触发会当成两件事。正确是合并成一个，只留真正不同的分支。
- **用「不要」来立规矩**。被禁的行为因此变得显眼。正确是写正面目标，让被禁的那件事根本不出现在文字里。
- **把文档写成了给执行者看的散文**。该有的结构、判据、边界没有。正确是让每个概念自己带齐邻居，让每一步都带一个可判定的收尾。
